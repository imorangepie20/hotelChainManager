# 관리자 참조 화면과 호텔 구조 분석

2026-09-10. 사용자 Chrome의 Codex LB를 읽기 전용으로 확인했다. 관찰한 디자인과 호텔 적용 제안을 구분한다. 제품 코드·API 동작을 분석한 결과는 아니다.

| 확인 화면 | 관찰한 구성 | 호텔 적용 제안 |
|---|---|---|
| Dashboard | 상단 메뉴, 지표 카드, 도넛 차트, 상태 요약 | 본사 전체 현황·지점 비교 |
| Reports | 기간 단축 선택, 날짜·다중 필터, 지표와 2열 차트, 빈 상태 | 매출·점유율·취소율 분석 |
| Accounts | 왼쪽 검색·정렬·목록, 오른쪽 상세, 상태 배지와 추이 | 지점·객실 상세, 예약 선택 후 배정 |
| APIs | 요약 지표, 차트, 검색 목록과 상세 선택 빈 상태 | 직원·객실 유형 관리의 목록 구조 |
| Settings | 섹션별 카드, 왼쪽 설명·오른쪽 입력, 구분선 | 공통 정책과 지점 예외 설정 |
| Advanced → Automations | 작업 목록과 실행 기록 분리, 검색·필터, 빈 상태 | 고객 요청 처리 목록·변경 이력 |

공통 시각 언어는 밝은 회색 배경, 흰색 카드, 얇은 테두리, 둥근 모서리, 작은 선형 아이콘, 파란 주요 버튼, 보조 설명의 낮은 강조다. 데이터 없음·미선택 상태를 명확히 안내한다. 정확한 CSS 토큰은 추출하지 않았다.

SDTPL_ADM의 공통 컴포넌트를 구현 기반으로 사용한다. 참조의 상단 메뉴를 그대로 복제하기보다 호텔 관리의 많은 메뉴는 테마 내비게이션에 배치하고, 콘텐츠 영역에 관찰한 카드·필터·상세 구성을 적용하는 것을 제안한다. 참조 화면의 과도한 빈 공간이나 작은 보조 글자는 호텔 작업 밀도에 맞게 조정한다.

본사와 지점은 같은 관리자 앱 안에서 역할·지점 권한으로 구분한다. 본사는 기간별 비교, 지점은 당일 작업을 우선한다. 예약 상태·객실 배정·청소 상태는 별도 필드와 배지로 표현하며, 서버가 지점 권한을 검증한다.
