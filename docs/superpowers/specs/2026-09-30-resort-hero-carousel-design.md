# 리조트 랜딩 5장 히어로·격자 전환 설계

날짜: 2026-09-30
상태: 독립 최종 리뷰 차단사항 수정·전체 회귀 완료, 배포·운영 연결 대기
관련 자산: [리조트 메인 미디어 자산 15개 등록](../../changes/2026-09-30-resort-main-media-assets.md)

## 1. 목표

속초·설악산·제주 랜딩에 관리자 미디어 자산 5개를 순서대로 연결하고 고객 웹 히어로에서 자동·수동 전환한다. 전환은 Motion for React를 사용해 이전 이미지가 왼쪽 열부터 격자 타일로 사라지고 다음 이미지가 같은 방향으로 순차 등장하게 한다.

문구·예약 기능과 콘텐츠 발행 권한은 기존 구조를 유지한다. 애니메이션 프레임워크는 표현만 담당하며 이미지 순서·대체 텍스트·공개 여부는 Spring Boot의 발행 snapshot이 결정한다.

## 2. 콘텐츠 계약

새 랜딩 문서는 다음 필드를 추가한다.

```json
{
  "heroSlides": [
    {
      "assetId": "미디어 UUID",
      "image": "/api/website/media/{assetId}/content",
      "alt": "페이지 문맥의 한국어 또는 영어 대체 텍스트"
    }
  ]
}
```

- `heroSlides`가 있으면 정확히 5개여야 한다.
- 다섯 `assetId`는 UUID로 파싱한 정규 값 기준으로 서로 달라야 한다. UUID 형식과 중복은 미디어 조회 전에 검증한다.
- 각 항목은 활성 자산 UUID, 서버 전달 경로와 일치하는 `image`, 1~200자의 `alt`를 가진다.
- 서버는 첫 항목을 기존 `heroAssetId`, `heroImage`, `heroAlt`에 미러링한다. 기존 SEO·미리보기·구 버전 reader가 첫 이미지를 계속 읽을 수 있게 하기 위함이다.
- `heroSlides`가 없는 과거 snapshot은 기존 단일 이미지 계약으로 계속 읽고 발행한다. 과거 JSON을 일괄 수정하지 않는다.
- 새 관리자 편집기는 과거 단일 문서의 1번만 수정할 때 legacy 계약을 유지한다. 2~5번을 사용해 `heroSlides`로 승격한 문서는 다섯 슬롯을 모두 채워야 서버가 저장한다.
- 별도 DB migration은 만들지 않는다. 랜딩 콘텐츠는 현재 JSONB 문서와 발행 snapshot에 저장되며 확장은 additive다.

## 3. API·미디어 정합성

`WebsiteMediaReferenceService`는 랜딩의 다섯 슬라이드 모두에 다음 규칙을 적용한다.

- 저장 시 자산 UUID와 전달 경로를 정규화한다.
- `website_media_usage`에 `heroSlides[0].assetId`부터 `heroSlides[4].assetId`까지 초안·발행 사용 위치를 기록한다. 미러 필드는 중복 usage로 기록하지 않는다.
- 경로 기반 공개 응답과 legacy 호텔 콘텐츠 응답의 `mediaVariants`에 다섯 자산의 준비된 WebP variant를 응답 시점에 포함한다. 손상된 과거 배열이 있어도 legacy `heroAssetId` variant는 항상 수집해 고객 fallback을 보장한다.
- 자산 일괄 교체는 모든 슬라이드 참조를 검사하고 교체한 정확한 필드 경로를 반환한다. 첫 슬라이드가 바뀌면 미러 필드도 새 값으로 다시 정규화한다.
- 자산이 보관됐거나 경로가 일치하지 않거나 개수·중복·alt 계약이 틀리면 초안 저장을 거부하며 현재 발행본은 바꾸지 않는다.

## 4. 관리자 편집

기존 대표 이미지 한 칸을 `메인 이미지 1`부터 `메인 이미지 5`까지의 고정 슬롯으로 바꾼다.

- 각 슬롯은 기존 `MediaField`의 선택·교체·미리보기·대체 텍스트 편집 기능을 재사용한다.
- 과거 단일 이미지 문서를 열면 1번 슬롯에 기존 자산을 표시하고 2~5번은 빈 상태로 보인다.
- 자산을 선택하면 기본 대체 텍스트를 복사하되 페이지 문맥에 맞게 수정할 수 있다.
- 같은 자산을 둘 이상의 슬롯에 선택할 수 없으며, 저장 전에 누락·중복을 화면에서도 안내한다. 서버 검증이 최종 권한이다.
- 1번 슬롯 변경은 기존 세 필드를 즉시 미러링한다.
- 다섯 슬롯이 완성되면 위로·아래로 이동 버튼으로 인접 항목을 원자적으로 교환한다. 첫 슬롯이 바뀌면 기존 세 필드도 같은 값으로 갱신한다.
- 390px에서는 슬롯이 한 열로 표시되고 모든 선택·대체 텍스트·저장 동작을 키보드로 수행할 수 있어야 한다.

## 5. 고객 히어로 전환

고객 웹은 `motion` 패키지의 React API를 사용한다.

- 기본 노출은 1번 이미지이고 5초마다 다음 이미지로 순환한다.
- 자동 전환 일시정지·재생, 이전·다음, 5개 위치 버튼을 제공한다. 버튼은 명확한 한국어·영어 접근성 이름과 현재 위치 상태를 가진다.
- 마우스 hover, 이미지 제어와 고정 예약 링크를 포함한 히어로 내부 키보드 focus, 페이지가 숨겨진 동안 자동 전환을 일시정지한다.
- 자동 전환은 live region으로 알리지 않고 사용자의 이전·다음·위치 선택만 `polite`로 알린다.
- 전환 중 중복 입력은 무시하고 완료 후 다음 5초를 다시 센다.
- 다음 이미지 원본 URL을 미리 로드한다. 첫 이미지에는 높은 fetch priority를 주고 나머지를 한꺼번에 eager load하지 않는다.

### 격자 효과

- 6열×4행, 총 24개 타일을 사용한다.
- 640px 이하는 4열×3행, 총 12개 타일로 줄인다.
- 이전 이미지 타일은 왼쪽 열부터 `opacity`와 `scaleX`가 줄어 사라진다.
- 다음 이미지 타일은 같은 왼쪽→오른쪽 순서로 나타난다. 행마다 짧은 보조 지연을 주어 기계적인 세로선 대신 부드러운 흐름을 만든다.
- 전체 전환은 약 1초 안에 끝나며 transform·opacity만 지속적으로 애니메이션한다.
- 문구, 예약 링크, 음영 레이어는 전환하지 않아 읽기와 클릭 위치를 유지한다.
- 타일은 `aria-hidden`이고 현재 슬라이드의 의미 있는 이미지 하나만 대체 텍스트를 제공한다.

### 움직임 축소

`useReducedMotion()`이 참이면 자동 순환을 시작하지 않고 사용자가 탐색할 때도 타일을 만들지 않은 채 180ms 페이드만 사용한다. CSS `prefers-reduced-motion`에서도 기존 히어로 문구 입장 애니메이션과 불필요한 transition을 제거한다.

### 성능 구현

- 실제 의존성은 `motion` `^13.4.4`다.
- `LazyMotion`의 `domAnimation` feature를 동적 chunk로 분리한다. 첫 의미 이미지와 문구는 feature chunk 완료를 기다리지 않고 렌더링한다.
- 리뷰 수정 후 로컬 production build에서 초기 앱 JS는 `476.48 kB`(`145.33 kB` gzip), 동적 Motion feature는 `39.00 kB`(`14.81 kB` gzip)이며 500kB chunk 경고가 없다.

## 6. 오류·하위 호환

- 공개 문서의 `heroSlides`가 정확한 5장 계약을 만족하지 않으면 전체 배열을 버리고 기존 단일 히어로를 사용한다. 부분 배열을 섞어 보여주지 않는다.
- 기존 단일 히어로나 정적 fallback은 슬라이드 한 장으로 렌더링하고 자동 전환·위치 버튼을 만들지 않는다.
- 잘못된 외부 URL, 다른 UUID의 전달 경로, 빈 값·200자 초과 alt, 대소문자만 다른 UUID 중복도 고객 parser에서 거부한다.
- 애니메이션 오류가 나도 예약 검색과 본문은 정상 동작하고 첫 이미지가 남아야 한다.

## 7. 검증과 완료 기준

1. API 통합 테스트가 legacy 단일 이미지, 정상 5장, 4장, 중복, 잘못된 경로, usage 5건, 공개 variant 5개, 자산 교체를 검증한다.
2. 관리자 Playwright가 5개 슬롯 선택, 대체 텍스트, 중복·누락 안내, 순서 이동, 저장 payload, 키보드와 390px를 검증한다.
3. 고객 parser 검사가 정상 5장과 모든 실패 fallback을 검증한다.
4. 고객 Playwright가 5초 자동 전환, 명시적 일시정지·재생, 이전·다음·위치 버튼, 전체 히어로 hover/focus 일시정지, 자동 전환 live-region 억제, reduced motion 자동 정지, 문구 고정, 320·360·390px 제어 노출과 44×44px 이상 실제 hit area를 검증한다.
5. API 대상 테스트, 관리자 TypeScript·대상 Playwright, 고객 단위 계약·프로덕션 build·대상 Playwright가 모두 통과한다.
6. 배포 후 각 지점에 정확히 5개 자산을 연결해 초안 저장·미리보기·발행 후 공개 페이지와 모바일에서 확인한다.
7. 변경 기록에는 실제 테스트 결과, 공개 검증 결과, 미검증 항목과 롤백 방법을 남긴다.

현재 로컬 구현·검증 결과와 남은 운영 단계는 [변경 기록](../../changes/2026-09-30-resort-hero-carousel.md)에 기록한다.
