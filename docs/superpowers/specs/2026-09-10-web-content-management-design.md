# 리조트 운영 수준 고객 웹 CMS 설계

최종 갱신: 2026-09-11

이 문서는 목표 설계다. 아래 페이지 트리·승인·미리보기·복원·다국어는 현재 구현 완료를 뜻하지 않는다. 실제 상태와 검증은 [구현 계획](../plans/2026-09-10-web-content-management.md)과 [변경 기록](../../changes/2026-09-10-web-content-management.md)을 따른다.

## 제품 기준
고객 웹의 지점 소개만 수정하는 도구가 아니라, 본사가 여러 지점·언어·캠페인 페이지를 지속 운영하는 콘텐츠 플랫폼이다. 운영자는 개발자 없이 페이지 구성, 텍스트, 미디어, SEO, 노출 시점과 발행 상태를 관리한다.

## 콘텐츠 모델
- **사이트 설정**: 브랜드명, 공통 헤더·푸터, 연락처, 약관 링크, 기본 SEO.
- **지점**: 속초·설악산·제주도별 로컬 언어, 주소·교통·체크인 안내, 지점 SEO.
- **페이지 트리**: 홈, 지점 랜딩, 객실, 다이닝, 경험, 오퍼, 이벤트, 안내 페이지의 슬러그·메뉴 노출·상태.
- **블록**: 히어로, 리치 텍스트, 객실·오퍼 참조, 카드 그리드, 이미지·동영상, CTA, FAQ, 안내 표. 블록은 순서·표시 조건·다국어를 가진다.
- **미디어**: 파일 메타데이터, 대체 텍스트, 저작권·사용 기간, 파생 이미지, 사용 위치.
- **검색/SEO**: 제목, 설명, 대표 이미지, canonical, robots, 구조화 데이터 초안.

객실 유형·가격·재고·예약 가능 여부는 CMS 블록에서 참조할 수 있지만 원본은 예약 도메인에서 소유한다.

## 발행 워크플로
`초안 → 검토 요청 → 승인 → 즉시/예약 발행 → 보관` 상태를 가진다. 공개 고객 웹은 항상 최신 **발행본**만 읽는다. 초안은 인증된 미리보기 URL에서만 확인한다. 발행마다 불변 버전과 변경 요약·작성자·시각을 남기며, 이전 발행본은 복원할 수 있다.

## 권한
- `HQ_ADMIN`: 전체 사이트, 지점, 미디어, 발행·복원·권한 관리.
- `HQ_EDITOR`: 초안 생성·수정·검토 요청, 발행 불가.
- `BRANCH_STAFF`: 운영 콘텐츠는 읽을 수 있어도 고객 웹 발행은 불가.
- 모든 저장·발행·복원은 서버에서 역할을 확인하고 감사 로그에 기록한다.

## 관리자 UX
관리자 메뉴는 `웹사이트` 아래 대시보드, 페이지, 오퍼/이벤트, 미디어, SEO, 발행 이력으로 구성한다. 편집기는 왼쪽 페이지 트리, 중앙 블록 캔버스, 오른쪽 설정 패널을 제공한다. 초안/발행 상태, 언어, 지점, 예정 발행 시간을 상단에서 명확히 표시한다. 저장과 발행은 분리하고, 발행 전 변경 요약과 영향을 받는 URL을 보여준다.

## 단계적 구현
1. 콘텐츠 문서·버전·감사 로그와 본사 권한, 공개 발행본 조회.
2. 현재 고객 화면의 지점 랜딩 콘텐츠를 관리자 편집·즉시 발행으로 이전.
3. 페이지·블록·다국어·SEO와 미리보기 URL.
4. 미디어 라이브러리·예약 발행·변경 비교·복원.

외부 이미지 저장소, 번역 승인, 다단계 결재, CDN 무효화는 4단계 이후 연결한다. 각 단계에서 고객 예약 API와 분리된 계약을 유지한다.

## 현재 구현과 목표의 차이
- 현재 편집 대상은 지점 랜딩의 히어로·설명·경험·오퍼·도착 안내와 선택 SEO 제목·설명이다. 기본 운영은 폼에서 수행하고 고급 JSON 편집도 제공한다. 경험·오퍼는 카드 단위로 추가·삭제·순서 변경할 수 있으며, 고객 화면 형태의 미리보기를 제공한다. 공통 헤더·푸터, 별도 페이지와 미디어 라이브러리는 아직 관리하지 않는다.
- 현재 흐름은 본사 초안 저장→즉시 발행이다. 승인·예약 발행·복원·인증 미리보기는 계획이다.
- 현재 역할은 HQ_ADMIN과 BRANCH_STAFF이며 CMS 관리 조회·저장·발행·이력 조회는 모두 HQ_ADMIN만 허용한다. HQ_EDITOR는 미구현이다.
- 공개본 조회와 정적 기본값 폴백은 고객 웹에 연결했다. 실제 HTTP 저장·발행과 공개 API 반영은 검증했으며 로그인된 관리자 UI에서 고객 브라우저까지 잇는 검증은 남아 있다.
- 현재 버전 이력은 번호·발행 시각을 반환한다. 변경 요약·비교·복원 UI는 후속 작업이다.
- 히어로·도착 안내·경험·오퍼의 전체 랜딩 스키마와 초안·발행 버전 기반 낙관적 충돌 제어를 구현했다. 선택 SEO 객체는 제목·설명을 모두 요구하고 60자·160자로 제한한다. 고객 웹은 발행본 SEO를 브라우저 제목과 설명 메타에 반영하며, canonical·OG·robots와 검색 크롤러 렌더링은 페이지 URL/SSR 또는 prerender 도입 뒤에 구현한다.
- `website_page`가 지점 랜딩의 페이지·경로·메뉴·콘텐츠 발행 기준이다. 기존 `hotel_web_content`는 이전 endpoint 호환과 이관 원본으로 남기며, 기존 endpoint도 새 랜딩 페이지를 읽고 쓴다. 첫 트리는 `숙소` 아래 속초·설악산·제주도 랜딩이며, 본사는 슬러그·메뉴명·노출·순서를 콘텐츠와 같은 초안/발행 버전으로 관리한다.
- 공개 고객 웹은 `GET /api/website/navigation`과 `GET /api/website/pages/resolve?path=...`의 발행본만 사용하며 `/stays/:slug`을 렌더한다. 신규 페이지 생성·이동과 범용 블록·다국어는 아직 없다.
