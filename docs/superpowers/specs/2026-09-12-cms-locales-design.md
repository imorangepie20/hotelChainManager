# CMS 언어별 초안·발행 설계

기준: 기존 롯데리조트급 CMS 설계 6.2와 사용자의 진행 지시. 한국어·영어 지원은 신규 요구가 아니라 기존 기획의 구현이다.

## 범위와 호환 이관

- 페이지 identity·부모·종류·지점은 공유한다. 한국어는 기존 `website_page` 및 호환 API를 계속 단일 원본으로 사용한다. 영어는 추가 `website_page_translation`으로 분리한다. 한국어 저장 모델의 물리적 이전은 이번 확장 단계에서 하지 않는다.
- 기존 한국어 URL, 콘텐츠, 버전, 이력, redirect, 자산 UUID는 수정·재발행하지 않는다. 새 migration은 번역 테이블과 locale별 media usage 식별자만 추가한다.
- 영어 초안은 본사가 명시적으로 한국어 초안을 가져온 뒤 번역한다. 가져온 내용은 번역 완료로 간주하지 않으며 자동 발행하지 않는다. 조회만으로 DB를 변경하지 않는다.
- 영어 콘텐츠·메뉴·SEO·alt·캡션, 초안/발행 버전과 발행 이력은 독립적이다. 영어 저장·발행은 한국어 초안·발행본을 변경하지 않는다. 한국어 수정도 영어 발행본을 변경하지 않는다.
- 영어 경로는 `/en` + 한국어 구조 경로이며 홈은 `/en`이다. 첫 단계는 구조 슬러그를 공유하며 언어별 임의 slug 편집은 제외한다. 영어의 현재 발행 경로는 한국어 이동만으로 변경하지 않는다. 영어 재발행 시 경로가 바뀌면 이전 영어 경로를 같은 locale의 단일 301로 보존한다.
- 객실·지점 연결은 유효한 예약 도메인 ID만 허용한다. 영어 발행본은 발행 시점 연결 snapshot을 사용한다. 가격·재고·예약 API는 변경하지 않는다.

## 관리자와 공개 API

- 기존 본사 전용 page API는 한국어 호환 경로다. `/pages/{id}/translations/en` GET/POST/PUT, `/publish`, `/versions`를 영어 독립 경로로 제공한다. GET은 없으면 version 0·빈 콘텐츠를 반환한다. POST는 한국어 source draft와 lifecycle version을 확인해 초안을 생성한다.
- 본사 CMS에 한국어/영어 선택과 언어별 상태를 제공한다. 미저장 언어 전환은 기존 확인 dialog로 보호한다. 영어 초안이 없으면 가져오기 버튼만 제공한다. 구조 이동·페이지 전체 보관·복원·삭제·과거 한국어 비교는 한국어 화면에서 수행한다.
- 공개 navigation/resolve/collection은 `ko`/`en`만 받는다. locale 생략은 기존 한국어, `/en` 경로는 영어로 해석한다. 영어 발행본이 없으면 404/빈 목록이며 한국어 콘텐츠로 fallback하지 않는다.
- 고객 웹은 `/en` 경로와 해당 locale의 API·메뉴·CMS 콘텐츠를 사용한다. 영어 누락 안내를 제공한다. 예약·결제·AI 전체 UI의 영어화는 이 콘텐츠 단계에 포함하지 않는다.
- 페이지 전체 보관은 두 언어 공개본과 공개 usage를 중단한다. 복원은 초안만 유지하며 영어도 재발행해야 한다. 페이지 영구 삭제는 번역과 번역 이력도 삭제하고 자산은 보존한다.

## 오류와 안전

- 모든 영어 쓰기는 본사 권한, 활성 page, optimistic version, 실제 미디어·콘텐츠 validator를 사용한다. publish 직전에 재검증한다. locale별 usage가 다른 언어 저장 때문에 제거되지 않아야 한다.
- 보관·삭제·번역 쓰기는 page row 잠금 순서를 공유한다. 언어 간 요청은 개별 버전으로 충돌을 판단한다. 늦은 UI 응답은 page/locale 변경 후 적용하지 않는다.
- 한국어 호환 API와 추가 영어 테이블은 새 앱 안에서 공존한다. 이전 바이너리는 locale 없는 usage 삭제를 수행하므로 혼합 버전 CMS 쓰기는 허용하지 않는다. 롤백 시 영어 테이블·usage는 보존하고 CMS 쓰기를 차단한 읽기 전용 상태로 운영한다. Flyway validation도 V20을 인식하는 호환 빌드가 필요하며 단순 이전 바이너리 교체가 안전한 롤백은 아니다. 테이블 삭제나 데이터 축소 migration은 수행하지 않는다.

## 완료 기준

실제 PostgreSQL 통합 테스트에서 번역 미발행 비노출, 언어 독립 저장/발행/이력/usage, 권한·stale version·보관/복원/삭제, 영어 redirect를 확인한다. 관리자 직접 E2E는 초안 생성·영어 저장/발행·전환 경고·키보드/모바일을 검증한다. 고객 경로/parser 직접 테스트·타입·build 및 영어 누락/발행 화면을 확인한다. 사용자 실제 CMS에는 검증용 저장·발행·보관·삭제를 하지 않는다.
