# 고객 웹 리조트 경험 업그레이드 설계

## 목표

고객 웹의 첫 화면을 속초·설악·제주 여행을 발견하고 실제 객실 예약으로 이어지는 리조트 수준의 브랜드 경험으로 재구성한다. 기존 Spring Boot 검색·재고 확보·테스트 결제·예약 취소 API 계약은 변경하지 않는다.

## 근거와 방향

롯데리조트 속초의 공개 화면을 분석했다. 큰 장소 이미지, 짧은 감성 카피, 객실·다이닝·시설을 잇는 에디토리얼 모듈, 기간과 혜택이 명확한 오퍼, 반복되는 예약 진입점이 핵심 구조다. 이를 참고하되 로고·문구·사진·UI 자산은 복제하지 않는다.

우리 고객 웹은 `STAY HANEUL`의 차분한 네이비·청록·아이보리 톤을 유지한다. 지점별 장소성은 속초의 동해, 설악의 산림, 제주의 화산섬으로 구분한다. 객실 가격과 잔여 객실은 기존 API가 반환한 값만 표시하며, AI는 후속 연결 지점으로만 보여준다.

## 화면 구조

1. **전역 헤더**: 투명 헤더에서 스크롤 시 아이보리 배경의 고정 헤더로 전환한다. 호텔·객실·경험·오퍼·예약 메뉴와 예약 조회 진입점을 제공한다.
2. **목적지 히어로**: 지점 선택 상태에 맞는 대형 이미지, 목적지명, 한 줄 소개, 예약 CTA를 보여준다. 속초가 초기 선택이며 지점 전환은 같은 페이지에서 콘텐츠를 바꾼다.
3. **예약 바**: 히어로 하단과 긴 콘텐츠 이후에 재사용한다. 지점·체크인·체크아웃·성인 수를 입력하고 기존 `/api/availability`로 검색한다. 키보드와 모바일에서 동작해야 한다.
4. **여정 콘텐츠**: 객실, 다이닝, 경험을 3개 카드로 제안한다. 각 카드에는 지점 맞춤 사진·제목·설명·세부 탐색 CTA를 둔다. 첫 버전 CTA는 해당 예약 바 또는 페이지 섹션으로 이동한다.
5. **스페셜 오퍼**: 실제 예약 API의 요금제가 아닌 고정 에디토리얼 콘텐츠다. 예약 기간·투숙 기간·핵심 혜택을 표시하고 예약 바로 이동한다. 가격과 재고를 직접 주장하지 않는다.
6. **현장 안내와 AI**: 체크인·아웃, 위치, 계절별 추천을 안내한다. AI 예약 도우미는 준비 중 상태이며 실제 예약을 만들거나 가격을 제시하지 않는다.
7. **검색 결과와 예약 관리**: 현재 객실 비교, 고객 정보, 테스트 결제, 취소 화면을 시각 체계에 맞게 정리하되 모든 상태 전이와 세션 복구는 유지한다.

## 컴포넌트와 데이터 경계

`App.tsx`는 예약 상태와 API 호출을 계속 소유한다. 새 `destination-content.ts`는 지점별 히어로·객실·경험·오퍼·현장 안내용 정적 콘텐츠만 제공한다. 프레젠테이션 컴포넌트는 이 콘텐츠와 예약 상태 콜백을 받아 렌더링하며 API를 직접 호출하지 않는다. 스타일은 `styles.css`를 섹션별 클래스와 반응형 규칙으로 분리한다.

이미지는 포트폴리오용 가상 호텔 자산만 `public/images`에 저장한다. 실제 롯데리조트 사진이나 텍스트를 가져오지 않는다.

## 반응형·접근성

- 390×844에서는 메뉴가 대화형으로 열리고, 예약 바는 한 열로 배치한다.
- 모든 메뉴·CTA·예약 폼은 키보드 포커스와 명확한 이름을 가진다.
- 사진은 목적지를 설명하는 대체 텍스트를, 장식 이미지는 빈 대체 텍스트를 사용한다.
- 검색·확보·결제·취소 상태는 기존 `role=status` 안내를 유지한다.

## 검증 기준

- `pnpm build`가 통과한다.
- 기존 검색 → 객실 선택 → 확보 → 테스트 결제 → 예약 취소 흐름이 바뀌지 않는다.
- 390×844와 데스크톱에서 히어로, 예약 바, 콘텐츠 카드, 검색 결과가 가로 스크롤 없이 표시된다.
- 키보드만으로 메뉴, 지점 선택, 날짜·인원 입력, 검색 실행을 할 수 있다.

## 제외 범위

다국어 전환, 실제 CMS, AI 대화 UI, 객실 상세 라우팅, 실제 결제·이메일 발송은 이번 화면 업그레이드에 포함하지 않는다.
