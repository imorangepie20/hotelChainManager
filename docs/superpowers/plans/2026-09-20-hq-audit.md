# 본사 감사 이력 통합 조회 첫 단계

> 상태: 구현 완료. 최종 갱신: 2026-09-20.

## 배경

- `admin-menu-roadmap.md` 7번 `감사·이력 조회`가 다음 대상이었다. 1·2·3·5번 메뉴의 읽기·첫 쓰기 동작은 끝났다.
- V29~V37 감사 테이블(예약자 정정·인원·객실 재배정·일정 변경·취소·운영 상태 전환·투숙 중 이동)과 `reservation_change_event`는 데이터가 쌓이고 있으나, 본사가 읽는 API와 화면이 없었다.
- 각 서비스가 감사 표에 직원 id만 남기므로, 본사가 "누가, 언제, 무엇을 바꿨는지"를 한 화면에서 보려면 직원 이름과 예약 정보를 조인해야 했다.

## 완료 기준

1. `GET /api/staff/audit`가 본사 세션으로 감사 이력을 통합해 반환한다. SELECT만 사용하고 상태를 변경하지 않는다. **완료.**
2. 응답은 감사 유형(`GUEST_UPDATE`·`PARTY_UPDATE`·`ROOM_REASSIGNMENT`·`STAY_CHANGE`·`CANCELLATION`·`ROOM_OPERATIONAL_TRANSITION`·`CHECKED_IN_ROOM_MOVE`·`CHANGE_REQUEST_EVENT`)을 묶어 발생 시각 내림차순으로 정렬한다. **완료.**
3. `reservationId`·`hotelId`·`from`·`to`·`limit`·`offset` 필터를 지원한다. `limit`은 1~200, `offset`은 0 이상이고 위반은 400이다. **완료.**
4. `HQ_ADMIN`만 호출 가능. 지점 직원 403, 잘못된 세션 401, 없는 지점 404. **완료.**
5. 각 이력에는 처리 직원 이메일·이름·역할, 지점 이름, 예약 id·고객 이름(있을 때), 객실 번호(있을 때), 이전·이후 요약이 포함된다. 원본 JSON은 노출하지 않는다. **완료.**
6. 관리자 4001 `/dashboard/audit`의 `감사 이력` 화면이 유형별 표와 더 보기 페이지 이동을 쓴다. `nav.ts`의 `본사 관리` 그룹에 노출한다. **완료.**
7. 서버 통합 테스트와 관리자 TypeScript·ESLint·Playwright 시나리오가 종료 코드 0이다. **완료.**

## 구현 범위

### 서버 (services/api)

- `audit/AuditQueryService`: 8종 감사 표를 `UNION ALL`로 묶어 최신순으로 읽는다. 모든 쿼리가 SELECT다.
  - `reservation_guest_change` → `GUEST_UPDATE`. 이전 이름·이메일 → 새 이름·이메일.
  - `reservation_party_change` → `PARTY_UPDATE`. 이전 성인·아동 → 새 성인·아동.
  - `reservation_room_assignment_change` → `ROOM_REASSIGNMENT`. 이전 객실 번호 → 새 객실 번호.
  - `reservation_stay_change` → `STAY_CHANGE`. 이전 날짜·총액 → 새 날짜·총액과 차액 안내.
  - `cancellation_attempt` → `CANCELLATION`. 직원(`actor_type = 'STAFF'`) 취소만 노출하고 환불액·환불 상태.
  - `physical_room_operational_event` → `ROOM_OPERATIONAL_TRANSITION`. 이전 상태 → 새 상태와 사유.
  - `checked_in_room_move` → `CHECKED_IN_ROOM_MOVE`. 이전 객실 → 새 객실과 이동 사유.
  - `reservation_change_event` → `CHANGE_REQUEST_EVENT`. `actor_staff_id`가 있는 전환만 노출한다.
- `audit/AuditController`: `GET /api/staff/audit`. `requireHeadquarters`로 본사만 허용한다.
- `audit/AuditQueryFilters`·`AuditEventView`·`AuditEventsView`.
- 기존 감사 표에 컬럼을 추가하거나 제약을 변경하지 않았다. additive 마이그레이션도 없다.

### 관리자 (SDTPL_ADM)

- `staff-api.ts`에 `getAuditEvents`·`AuditEvent`·`AuditEvents`·`AuditEventType`·`auditEventLabels`를 추가했다. 403·기타 실패 안내를 나눴다.
- `components/hotel-admin/audit-events.tsx`: 유형별 표와 더 보기 페이지 이동. `HQ_ADMIN`만 노출.
- `nav.ts`의 `본사 관리` 그룹에 `감사 이력`(`/dashboard/audit`, `History` 아이콘)을 추가했다.

### 테스트

- `AuditIntegrationTest` 13종: 본사 전체 조회 8건·유형별 노출, 시각 내림차순 정렬, 지점 403, 잘못된 세션 401, 예약 필터 6건, 지점 필터 0건, 기간 필터, 역순 기간 400, limit 0·201 400, offset -1 400, 두 번째 페이지 이동, 없는 지점 404, 요약 노출.
