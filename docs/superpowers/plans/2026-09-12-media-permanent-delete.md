# CMS 미디어 자산 영구 삭제 구현 계획

## 목표

본사 관리자가 참조 없는 보관 업로드 자산을 보관 후 30일이 지난 시점부터 영구 삭제하고, 카탈로그 행과 실제 저장 파일을 함께 정리한다.

## 범위와 정책

- `UPLOADED`, `ARCHIVED`, 사용 위치 0건, 보관 후 30일 경과 자산만 삭제한다.
- 번들 자산, 활성 자산, 참조 자산, 유예 기간 안의 자산과 오래된 버전 요청은 서버에서 거부한다.
- 기존 보관 자산의 보관 시각은 migration 적용 시점의 `updated_at`으로 보정한다.
- 기존 서버와의 호환을 위해 `archived_at`은 nullable로 추가하고 즉시 강제 제약을 걸지 않는다. 값이 없는 보관 자산은 삭제할 수 없다.
- 저장 파일은 같은 볼륨의 격리 경로로 이동한 뒤 DB 행을 삭제한다. 트랜잭션이 롤백되면 파일을 복구하고, 커밋되면 격리 파일을 제거한다.
- 파일 교체는 이번 범위에 포함하지 않는다.

## 구현 순서

1. 서버 통합 실패 테스트로 성공 삭제와 보호 조건을 고정한다.
2. V19 migration, 응답 필드, 본사 전용 DELETE API와 파일 격리 삭제를 구현한다.
3. 관리자 E2E 실패 테스트로 삭제 가능일, 비활성 상태, 확인 대화상자와 목록 갱신을 고정한다.
4. 관리자 API 타입과 미디어 선택기 UI를 구현한다.
5. 대상 서버 테스트, 관리자 E2E·TypeScript·lint, migration 적용과 API readiness를 검증한다.

## 완료 기준

- 조건을 충족한 자산만 DB와 저장소에서 삭제된다.
- 실패 또는 롤백 시 카탈로그와 파일이 함께 유지된다.
- 관리자 화면은 서버 응답의 삭제 가능 시각을 표시하고 조건 충족 전에는 삭제를 실행하지 않는다.
- 실제 사용자 자산에는 삭제 요청을 보내지 않는다.
