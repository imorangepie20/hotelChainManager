# 리조트 운영 수준 CMS 구현 계획

최종 갱신: 2026-09-11

## 1단계: 발행 가능한 지점 랜딩 콘텐츠 — 진행 중
- [x] 콘텐츠 문서·버전·감사 로그 스키마와 개발 DB 적용.
- [x] 개발 프로필의 3개 지점 초기 콘텐츠 이관. 기존 편집 문서 보존.
- [x] 본사 전용 관리 API와 공개 발행본 조회 구현.
- [x] 고객 웹 공개본 조회·정적 기본값 폴백 연결 및 빌드.
- [x] 관리자 JSON 편집기 구현과 실제 `/dashboard/website` 페이지 경로 수정.
- [x] 초안과 공개본 분리 서비스 통합 테스트, 3개 지점 공개 API 조회.
- [x] 관리자 전체 빌드와 `/dashboard/website` 라우트 생성·E2E 진입 확인.
- [x] 본사 실제 HTTP 저장→발행→공개 API 반영, 버전·감사 로그 확인.
- [x] 지점 계정 CMS 조회·저장·발행 HTTP 403 확인.
- [x] 미저장 편집 발행 방지·지점 전환 경고·오류 UX 보완.
- [ ] 실제 본사 로그인으로 관리자 UI 저장·발행 후 고객 브라우저 새로고침 반영 확인.
- [x] 필수 제목 검증과 낙관적 버전 기반 동시 편집·발행 충돌 처리 및 실제 HTTP 409 검증.
- [x] 히어로·도착 안내·경험·오퍼 전체 콘텐츠 스키마 검증. 배열은 비어 있을 수 있으나 카드가 있으면 각 필수 필드를 검증한다.

서비스 통합 테스트 통과는 실제 관리자 발행 흐름 완료를 의미하지 않는다. 초기 DB 콘텐츠와 정적 기본값이 같으므로 실제 문구를 변경해 고객 반영을 확인한다.

## 2단계: 페이지와 블록 편집 — 계획
- [x] 히어로·경험·오퍼·도착 안내 폼 편집과 경험·오퍼 카드 추가·삭제.
- [x] 확장 필드와 복구를 위한 고급 JSON 편집 유지.
- [x] 경험·오퍼 카드 추가·삭제·위아래 순서 변경과 고객 화면 형태의 미리보기.
- [x] 지점 랜딩 SEO 메타데이터: 선택 `seo.title`·`seo.description`을 본사 폼에서 편집하고, 발행본만 고객 브라우저 제목·설명에 반영한다. 제목은 60자, 설명은 160자로 제한한다.
- [x] `website_page` 기반의 사이트 → 숙소 → 3개 지점 랜딩 트리, 발행 경로·슬러그·메뉴명·노출·순서를 추가했다. 발행 경로는 `/stays/sokcho`, `/stays/seoraksan`, `/stays/jeju`이며 고객 웹의 공개 resolve API와 연결했다.
- 블록 순서와 CTA, 한국어·영어 필드를 추가한다.
- 인증된 초안 미리보기, canonical·OG·robots와 검색 크롤러용 렌더링은 페이지 URL/SSR 또는 prerender 단계에서 추가한다.

## 3단계: 운영 자동화 — 계획
- 미디어 라이브러리와 자산 사용 위치를 관리한다.
- 예약 발행, 변경 비교·복원, 감사 조회를 추가한다.

## 후속 확장
본사 에디터 역할, 번역·다단계 승인, 외부 자산 저장소와 CDN 무효화는 별도 설계·검증 후 도입한다.

## 완료 기준과 검증 범위
- 공개 고객 웹에는 발행본만 노출하며 초안은 노출하지 않는다.
- 본사와 지점 권한을 서버에서 구분한다.
- 콘텐츠 변경 후에도 예약·요금·AI API의 책임을 유지한다.
- 변경한 영역의 테스트·앱 빌드·핵심 상호작용만 수행하고 미검증은 기록한다.
- [설계](../specs/2026-09-10-web-content-management-design.md), [검증 기록](../../changes/2026-09-10-web-content-management.md)을 함께 갱신한다.
