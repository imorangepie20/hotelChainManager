# 호텔·객실 지점 선택 상태 명확화 계획

> 상태: 구현·검증·커밋·배포 완료
> 날짜: 2026-09-26
> 작업 규모: standard

## 목표

- `호텔 및 객실` 화면에서 어떤 지점이 선택됐는지 시각적으로 즉시 확인할 수 있게 한다.
- 선택한 지점과 아래 객실유형 결과가 같은 지점임을 제목과 로딩 상태로 확인할 수 있게 한다.
- 연관된 `재고·가격` 화면도 서버의 동일한 지점 목록을 사용해 신규·개명·판매중지 지점과
  기본 선택이 어긋나는 구조를 없앤다.
- 기존 지점 조회, 객실유형 조회, 재고·가격 조회, 권한 및 쓰기 API 계약은 바꾸지 않는다.

## 현재 문제

- 호텔 표의 지점 선택은 지점명 버튼의 굵기 변화만 사용한다. 선택 행 배경,
  `aria-pressed`, 가시적인 `선택됨` 표식이 없다.
- 객실유형 카드 제목에 선택 지점명이 없어 표를 내린 뒤 현재 문맥을 재확인하기 어렵다.
- 지점 전환 요청 중 이전 지점의 결과 표가 남아 새 선택 표시와 실제 데이터가 잠시 어긋난다.
- `재고·가격` 화면은 서버 목록이 아니라 고정된 지점 배열을 사용한다.

## 작업 목록

1. 기존 E2E를 특성화 테스트로 보강한다.
   - 최초 지점과 전환 후 지점의 `aria-pressed` 상태
   - 선택 행의 `data-state="selected"`와 가시적인 `선택됨` 표시
   - 객실유형·재고 결과 제목의 현재 지점명
   - 선택한 지점 ID로 API가 호출되는지
   - 지점 전환 로딩 중 이전 지점 결과가 보이지 않는지
   - 390px 화면에서 선택기와 페이지 전체에 가로 넘침이 없는지
2. `hotel-catalog.tsx`의 기존 지점 관리 표를 유지하면서 선택 상태를 강화한다.
   - 기존 `TableRow`의 selected 상태 스타일 재사용
   - 선택 버튼에 `aria-pressed` 추가
   - 선택 지점에 `선택됨` 배지 표시
   - 객실유형 카드 제목에 선택 지점명 표시
3. 지점 전환 중 결과 문맥을 안전하게 만든다.
   - 새 지점을 선택하면 이전 지점 결과를 숨기고 해당 지점 로딩 안내를 표시한다.
   - 응답의 `hotelId`와 현재 선택 ID가 일치할 때만 결과를 표시한다.
4. `inventory-viewer.tsx`의 고정 지점 배열을 `getStaffHotels` 조회로 교체한다.
   - 서버 호텔 순서와 첫 유효 지점을 사용한다.
   - 선택 버튼 그룹에 접근 가능한 이름과 현재 지점 문맥을 추가한다.
   - 결과 제목에 선택 지점명을 표시하고 전환 중 이전 결과를 숨긴다.
5. 관련 검증과 기록을 수행한다.
   - 변경 전·후 Playwright: `hotel-catalog`, `inventory-viewer`, `inventory-mobile`
   - 관리자 TypeScript 검사와 변경 파일 대상 ESLint
   - 변경 기록과 현재 개발 상태 문서 갱신

## 완료 기준

- 마우스, 키보드, 보조기기에서 현재 선택 지점을 식별할 수 있다.
- 선택 행은 배경과 텍스트 표식을 함께 사용하며 색상만으로 상태를 전달하지 않는다.
- 객실유형과 재고 결과 제목에서 현재 지점명을 확인할 수 있다.
- 지점 전환 중 이전 지점의 객실유형·재고 결과가 새 선택 아래 노출되지 않는다.
- 두 화면이 서버의 동일한 호텔 목록을 사용한다.
- 관련 E2E, 타입 검사, 린트가 통과한다.

## 비범위

- API·DB 스키마·권한 정책 변경
- 가격·재고·예약 확정 로직 변경
- 화면 간 선택 지점 영구 저장 또는 URL 동기화
- 지점 관리 표를 완전히 다른 정보 구조로 재설계

## 변경 안전성

- 관련 컴포넌트와 E2E 파일은 이미 미커밋 변경이 있으므로 전체 교체하지 않고 국소 패치한다.
- 구현 전 관련 테스트가 통과하는지 먼저 확인한다. 실패하면 기존 실패와 이번 변경의 실패를
  구분해 기록한 뒤 진행한다.

## 완료 결과

- 호텔·객실 화면은 선택 행 배경, `aria-pressed`, `선택됨` 배지와 결과 제목의 지점명으로 현재 지점을 명확히 표시한다.
- 재고·가격 화면은 하드코딩 지점 목록을 제거하고 서버의 `getStaffHotels` 결과를 사용한다.
- 지점 전환 시 이전 결과를 숨기며, 응답의 지점 ID와 현재 선택이 일치할 때만 표시한다.
- 저장 중에는 지점 선택을 잠그고, 늦게 도착한 이전 지점의 객실 기본값·요금 상세 응답은 generation 검사로 폐기한다.
- 관련 Playwright 61건과 TypeScript 검사가 통과했다. ESLint는 오류 0건, Effect 내 상태 갱신 경고 6건이다.
- 독립 코드 리뷰에서 CRITICAL/HIGH 잔존 문제가 없음을 확인했다.
