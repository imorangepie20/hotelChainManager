# 토스페이먼츠 테스트 결제 연결

## 범위와 변경 이유

신규 예약과 예약 변경 추가 결제·부분 환불에 토스 테스트 결제 경로를 추가한다. 가격·재고·예약 확정은 서버가 검증하며 기존 가상 결제는 별도 모드로 유지한다. 라이브 키, 실제 과금, 외부 공개 터널과 운영 배포는 포함하지 않는다.

서버는 주문·금액·상점과 거래 키를 저장하고 승인·취소를 DB 잠금 밖에서 실행한다. 불명확한 결과는 재조회 대상으로 보존하며 재고를 반환하지 않는다. 전체 예약 취소는 저장한 모든 환불 계획이 검증된 뒤 완료한다. 고객과 관리자 취소 안내도 대기 응답을 완료로 표시하지 않는다.

## 검증 기록

- 백엔드 직접·인접 Maven 114건이 통과했다. `TossPaymentsHttpClientTest`, 신규 예약·변경 정산, 재고 만료, 변경 적용, 취소를 포함하며 PostgreSQL 16 테스트 DB에서 Flyway V40을 검증했다.
- 고객 순수 계약, TypeScript, production build가 통과했다. SDK 서버 입력, callback 정리, 권한 유실, provider 분기와 UNKNOWN 재조회 경로를 검사했다.
- 리뷰 전 고객 Playwright 11건과 기존 변경 결제 Playwright 2건은 통과했다. 재리뷰 수정 뒤 추가된 결제 재조회·provider 분기 Playwright 13건은 사용자가 main 고객 4000을 실행 중이라 해당 서버를 중단·교체하지 않고 미실행으로 남겼다. `--list`로 탐색만 확인했다.
- 관리자 취소 안내 직접 검사 4건과 TypeScript 검사가 통과했다. 기존 변경 결제 fixture는 실제 DTO 날짜와 fake provider 응답으로 맞췄지만, 같은 4000 보존 이유로 수정 뒤 브라우저 재실행은 하지 않았다.
- 독립 리뷰는 취소 실패 계획 재시도·대기열 기아, UNKNOWN 결과 재조회, Toss/fake 버튼 혼재를 지적했다. 저장 PG 키를 보존한 재시도, 공정 대기열, 권한 있는 lookup-only 재조회, 서버 provider 분기로 수정했고 재리뷰에서 중요 문제 없음으로 확인했다.
- 작업 시작 시 API 4080 readiness HTTP 200과 개발 DB V37을 읽기 전용 확인했다. 새 code의 개발 API 재빌드·migration 적용은 실행하지 않았다.

## 실제 sandbox와 미검증 범위

main의 Git 제외 `.env`와 실행 중인 API 환경에서 토스 클라이언트 키·시크릿 키·상점 설정이 없음을 값 출력 없이 확인했다. 사용자 상점의 실제 테스트 승인·조회·추가 결제·부분 환불·전체 취소는 수행하지 않았다. 가상 응답 기반 테스트는 실제 토스 거래 증거가 아니다.

외부 웹훅 전달은 승인된 공개 HTTPS 주소가 없어 미검증이다. 로컬 handler 검증은 웹훅 본문을 재조회 힌트로만 취급하는 계약을 대상으로 한다. 비밀값·카드 정보·원문 토큰·결제 키를 이 문서에 기록하지 않는다.

## migration과 롤백

V38·V39는 신규 결제 attempt와 고유 제약, V40은 변경 주문·환불 command·취소 이벤트 중복 방지·웹훅 조회를 추가한다. 기존 migration checksum을 변경하지 않는다.

롤백 시 먼저 신규 checkout 생성을 중지한다. 실행 중이거나 UNKNOWN인 command는 보존하고 조회·조정을 마친다. 토스 거래를 fake 환불로 처리하지 않으며 additive 테이블과 거래 감사 기록은 삭제하지 않는다. provider 설정을 바꾸는 것만으로 진행 중 정산이 해결되지는 않는다.

## 다음 작업

사용자 테스트 상점 설정 후 고객 4000/API 4080에서 실제 sandbox 승인·추가 결제·부분 환불·잔액 취소를 검증한다. 수정 뒤 고객·관리자 browser E2E도 사용자 서버를 종료하거나 새 포트로 대체하지 않는 조건에서 재실행한다. 공개 웹훅 전달과 운영 결제는 별도 환경·승인 범위다.
