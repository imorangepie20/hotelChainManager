# 직원 예약 취소

## 변경 이유

직원 예약 조회 화면에서 확정 예약의 취소 가능 여부와 예상 환불액을 서버 정책으로 확인하고, 권한이 있는 직원이 같은 화면에서 안전하게 취소할 수 있어야 한다.

## 구현 범위

- 기존 고객 취소의 저장 정책, 환불 gateway, 재고 복구와 멱등 처리 코어를 재사용한다.
- 본사 관리자 또는 예약 지점 직원만 취소 미리보기와 실행 API를 사용할 수 있다.
- 취소 미리보기는 현재 상태, 취소 가능 여부, 예상 환불액과 마감 시각을 반환한다.
- 직원 취소는 기존 `cancellation_attempt`에 직원 식별자를 남긴다.
- 예약 상세에서 환불액을 확인한 뒤 명시적으로 취소하고 결과 목록을 갱신한다.

## 완료 기준

- 확정 상태와 저장된 취소 마감 정책을 서버가 다시 확인한다.
- 환불 실패 시 예약과 재고가 유지되고, 같은 멱등 키의 재요청은 환불·재고 복구를 반복하지 않는다.
- 타 지점 직원은 미리보기와 실행 모두 거부된다.
- 취소 성공 시 확정 재고가 복구되고 처리 직원이 감사 데이터에 기록된다.
- 확인 대화상자는 키보드로 열고 취소할 수 있으며 모바일에서도 환불 정보와 실행 버튼을 확인할 수 있다.

## 제외 범위

- 날짜·객실 유형·인원·고객 정보 변경
- 취소 마감 이후의 예외 승인과 수동 환불
- 외부 결제사 연동

## 호환성과 롤백

- 감사 컬럼은 nullable/default 기반의 additive migration으로 기존 고객 취소 reader·writer를 유지한다.
- 애플리케이션 롤백 시 새 컬럼은 남겨도 기존 동작에 영향이 없다. 컬럼 제거는 새 애플리케이션을 모두 내린 뒤 별도 migration으로만 수행한다.

## 검증 결과

- `CancellationIntegrationTest` 9건 통과: 저장 정책 미리보기, 정확한 마감 시각 차단, 타 지점 권한 거부, 성공·실패 직원 감사 기록, 실패 멱등성, 환불·재고 복구와 기존 고객 취소 회귀를 확인했다.
- 예약 관리 Chromium E2E 1건 통과: 키보드 상세 열기, 모바일 폭, 취소 확인, API 실패 노출과 재시도, 성공 후 목록 갱신을 확인했다.
- 변경한 프런트 파일 ESLint, Next.js production build(정적 페이지 104개), UI detector를 통과했다.
- 실제 외부 결제사 환불과 운영 배포 환경은 이번 범위에서 검증하지 않았다.
