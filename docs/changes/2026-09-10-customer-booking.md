# 고객 예약 화면 연결

고객 웹을 4000 포트에서 실행하고 Spring Boot 4080 API로 검색·확보·테스트 결제·조회·취소를 연결했다. 기본 지점은 재고가 준비된 속초다. 검색 조건 변경 시 이전 결과를 제거하고, 새로고침하면 세션에 저장한 마지막 예약을 조회한다. 생성 요청 전 관리 토큰·멱등 키·본문을 세션에 저장해 응답 유실 시 같은 요청으로 재시도한다.

검증: 고객 앱 TypeScript·Vite 빌드 성공. 실제 브라우저에서 속초 2026-09-17~19 스탠다드 객실 검색, 확보, 결제 실패 안내, 결제 재시도 성공, 새로고침 후 확정 예약 복구, 취소 완료를 확인했다. 첫 Tab 키가 브랜드 링크에 도달하고 포커스 표시가 보이는 것도 확인했다. 실제 결제나 이메일 발송은 없다. 이전 백엔드 검증은 DB·검색·예약·결제/만료·취소 총 20개 테스트 통과다.

남은 작업: 모바일 390×844 실제 해상도 검증, 자동 E2E 파일, 만료 상태의 실제 시간 경과 UI 검증, 아동·다객실 검색, 다국어, 관리자와 AI 연결. 응답이 유실된 생성 요청이 있을 때 별도의 복구 화면을 제공하는 것도 후속 보완이다.

호텔 이미지는 built-in imagegen으로 생성해 `apps/web/public/images/sokcho-coast-hero.png`에 저장했다. 프롬프트 요지: 가상 속초 해안 호텔의 여명 건축 사진, 오른쪽 호텔과 왼쪽 바다 여백, 네이비·청록·아이보리, 텍스트·로고 없음.

## 리조트 경험 화면 업그레이드
- 롯데리조트 속초의 공개 정보 구조를 분석해 큰 목적지 히어로, 예약 바, 경험·오퍼·현장 안내를 고객 웹에 추가했다. 실제 자산·문구·로고는 사용하지 않고 가상 브랜드 `STAY HANEUL` 콘텐츠로 재구성했다.
- 선택 지점의 지역에 따라 속초·설악산·제주도 카피, 경험, 오퍼, 도착 안내가 바뀐다. 검색·재고 확보·테스트 결제·취소와 세션 복구 API 계약은 변경하지 않았다.
- `pnpm build` 통과. 390×844와 데스크톱에서 히어로와 예약 바, 콘텐츠 섹션의 표시를 확인했다. API 4080의 readiness와 호텔 목록 응답, 속초의 실제 객실 검색 결과, 설악산 전환 콘텐츠를 확인했다. 테스트 결제·취소는 기존 검증 결과를 유지하며 이번 화면 변경 뒤에는 재실행하지 않았다.

## 헤더 예약 조회 링크
- 브라우저 기본 파란 밑줄로 보이던 `예약 조회`를 네이비 유틸리티 링크로 정리했다. 44px 클릭 영역, 얇은 하단선, 청록색 호버와 기존 키보드 포커스 표시를 적용했다.
- 고객 웹 `pnpm build`와 실제 4000 브라우저 새로고침으로 네이비 텍스트·하단선 표시를 확인했다.

## 다객실 검색·예약 총액 일치
- 검색 API는 요청 객실 수로 재고와 객실 정원을 이미 검증하고 있었지만, 응답 `total`은 1객실 기준 일별 금액 합계만 반환하고 있었다. 2객실 이상에서 고객이 보는 총액과 예약 시 Spring Boot가 재계산하는 총액이 달라지는 문제를 수정했다.
- `AvailabilityService`가 검색 응답 총액에도 객실 수를 반영하며, 2객실 3박의 480,000원 요금이 960,000원으로 반환되는 통합 테스트를 추가했다.
- 고객 화면은 검색 조건 요약, 카드별 `객실 N개 · N박 총액`, 선택 카드 표시, 객실 선택 후 예약자 정보 영역으로의 부드러운 이동을 제공한다.
- 검증: `AvailabilityIntegrationTest` 6개 통과, 고객 웹 `pnpm build` 통과, 브라우저에서 검색 결과 요약과 객실 선택 → 예약자 정보 표시를 확인했다. 개발 API 컨테이너는 새 소스를 반영하도록 재빌드 중이며, 완료 뒤 2객실 실시간 API 확인이 필요하다.
