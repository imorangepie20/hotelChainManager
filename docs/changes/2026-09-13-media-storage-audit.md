# CMS 미디어 저장소 점검

## 목표와 완료 기준

본사 관리자가 DB 미디어 참조와 실제 로컬 저장 파일의 불일치를 삭제 없이 확인할 수 있게 한다.

- 업로드 원본과 storage key가 있는 variant 중 실제 파일이 없는 항목을 누락으로 보고한다.
- `.trash` 밖의 실제 파일 중 DB가 참조하지 않는 일반 파일을 orphan으로 보고한다.
- 생성 후 10분이 지난 참조 없는 `.tmp` 파일을 오래된 임시 파일로 분리한다. 10분 이내 임시 파일과 `.trash`는 진행 중 작업으로 간주해 제외한다.
- 결과에는 저장소 상대 key만 포함하고 절대 경로를 노출하지 않는다.
- `HQ_ADMIN`만 읽기 전용 점검 API와 CMS 결과 패널을 사용할 수 있다.

## 구현 순서와 검증

1. 실제 임시 저장소·PostgreSQL을 사용하는 API 회귀 테스트와 관리자 Playwright를 먼저 실패시킨다.
2. 별도 저장소 점검 서비스와 읽기 전용 endpoint를 추가한다.
3. 기존 미디어 선택기에 수동 점검 버튼, loading·정상·문제·오류 상태를 추가한다.
4. 대상 서버 테스트, 관리자 TypeScript·Playwright, 실제 개발 API의 읽기 전용 점검을 확인한다.

## 당시 제외 범위

이 변경 자체에는 파일 삭제·격리·자동 복구, 정기 scheduler, `.trash` 정리, 객체 저장소 이관과 알림을 포함하지 않았다. 이후 S3 호환 저장소별 점검과 수동 backfill은 [S3 미디어 저장소 이관](2026-09-13-s3-media-storage-migration.md)에서 구현했다.

## 구현 결과

- `HQ_ADMIN` 전용 `GET /api/staff/website/media/storage-audit`을 추가했다. 점검은 읽기 전용 transaction에서 업로드 원본과 READY variant의 storage key를 조회하고 로컬 저장소를 한 번 순회한다.
- 결과는 누락, 참조 없는 일반 파일, 10분 이상 지난 참조 없는 `.tmp`로 분리하고 key를 정렬한다. 진행 중일 수 있는 최근 `.tmp`와 `.trash` 전체는 결과에서 제외한다.
- 응답은 정규화한 상대 storage key만 제공한다. 절대·상위 경로 key는 응답에 포함하지 않고 점검 오류로 처리한다.
- 관리자 미디어 선택기에 수동 점검 영역을 추가했다. 정상·문제·오류를 같은 영역에 표시하며 점검 중 중복 요청을 막고 대화상자를 닫은 뒤 도착한 응답은 무시한다.
- 파일 삭제·복구·DB 수정은 추가하지 않았다.

## 검증 결과

- `WebsiteMediaIntegrationTest` 24건과 `WebsiteMediaVariantIntegrationTest` 22건, 합계 46건이 실제 PostgreSQL test DB에서 통과했다. 누락 원본, 유지되는 READY variant, orphan, 10분 경계의 오래된/최근 `.tmp`, `.trash` 제외, 파일 무변경, 정상 결과와 지점 권한 403을 포함한다.
- 관리자 Chromium E2E 2건이 통과했다. 문제 key 분류와 GET 요청, 정상 결과, 후속 오류 전환을 확인했고 후자는 390×844 viewport에서 실행했다. TypeScript 검사도 통과했다.
- 변경 파일 ESLint는 오류 0, 기존 경고 5건이었고 UI 패턴 탐지는 지적 0건이었다.
- 개발 API 이미지를 한 번 재빌드해 122개 production source와 16개 test source를 컴파일했고 health `UP`을 확인했다. 실제 개발 DB·named volume을 대상으로 읽기 전용 API를 호출한 결과 누락 0, orphan 0, 오래된 임시 파일 0의 정상 상태였다.
- 실제 관리자 `4001` 미디어 선택기에서 `저장소 점검`을 실행해 같은 정상 문구가 표시되는 것을 확인했다. 사용자 페이지·미디어·파일에는 mutation을 보내지 않았다.

## 미검증과 다음 작업

- 변경 경로 밖 전체 backend suite와 전체 관리자 E2E, 실제 운영 다중 인스턴스·대용량 파일 저장소 부하는 실행하지 않았다.
- 이 기록의 검증 수치는 로컬 점검 도입 당시 기준이다. 후속 S3 이관은 서버 119건, 관리자 E2E 8건과 격리 Compose 전환 검증을 별도로 완료했다.
- 자동 정리·복구는 점검 결과와 별도의 영향 확인·승인·감사 설계가 필요하다. 운영 provider와 CDN 계정·DNS·purge 연동은 여전히 후속 범위다.
