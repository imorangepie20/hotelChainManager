# 롯데리조트급 CMS 기능 재설계 기록

최종 갱신: 2026-09-12

## 변경 이유

사용자는 처음부터 롯데리조트 속초 수준의 디자인·UI·콘텐츠 운영을 목표로 제시했다. 기존 CMS는 초안·발행·이력·미디어 안전성에는 초점을 맞췄지만 일반 페이지가 `HERO`, `TEXT`, `CTA`만 지원해 객실·다이닝·부대시설·프로모션 상세 운영 범위에 미치지 못했다.

## 이번 작업

- 코드 구현을 추가하지 않고 CMS의 목표 기능을 다시 정의했다.
- 고객 공개 정보 구조, 콘텐츠 유형, block 계약, room type/지점 연결, 다국어, 권한, 검토·예약 발행, 미디어, URL 변경·SEO, 데이터 안전 기준을 설계했다.
- Archify로 본사 운영→CMS→콘텐츠 모델/미디어/예약 도메인→고객 공개 경계를 구조도로 만들었다.
- 가격·재고·예약 확정은 CMS가 아닌 Spring 예약 도메인에서 계속 검증한다는 경계를 명시했다.

## 확인 결과와 한계

- Archify 구조도는 showcase 구조 검사 9/9, 오류·경고 0으로 전달했다.
- 생성 artifact는 1440×900, 1600×1000, 1920×1080, 2048×1320 자동 브라우저 containment·readability 검사를 통과했다.
- 1440×900 light image를 시각 확인해 노드·연결·설명 카드의 겹침이 없음을 확인했다.
- 이 작업은 설계만 변경했다. 새 콘텐츠 유형, 블록, 권한, 데이터베이스 migration, 고객·관리자 UI, API는 아직 구현하지 않았다.

## 다음 작업

사용자가 요청한 대로 이 설계를 먼저 확정한 뒤, 콘텐츠 기반부터 기능 단위 구현 계획을 작성한다. 기존 사용자 페이지·자산은 설계 검증을 위해 변경하지 않는다.

## 1단계 상세 블록 고객·관리자 구현

- 서버의 `IMAGE_GALLERY`, `FEATURE_GRID`, `SPEC_TABLE`, `ACCORDION`, `NOTICE_LIST` 검증·미디어 usage 처리 위에 고객 웹 parser와 렌더러를 연결했다. parser는 서버와 같은 20개 블록 상한, 필드 allowlist, 배열 상한, 안전한 UUID 미디어 전달 경로와 안내 severity를 적용한다.
- 고객 화면은 갤러리의 이전/다음·썸네일 키보드 조작과 현재 위치 `aria-live`, semantic 사양 표, native `details` FAQ, 중요 안내 표시를 제공한다. 모바일에서는 갤러리·특징 카드·사양 표를 단일 열에 맞춘다.
- 본사 편집기는 다섯 block 추가와 항목 최소/최대 수를 제공한다. 갤러리 항목은 공통 미디어 선택기를 재사용하고, 미리보기는 저장·발행 없이 다섯 block을 고객 순서로 표시한다.

### 검증

- 사용자가 완료했다고 지정한 서버 `WebsitePageIntegrationTest` 15건은 재실행하지 않았다.
- 고객 parser 테스트는 Node 24의 TypeScript strip-types 실행으로 통과했고, 고객 웹 `pnpm.cmd build`를 통과했다.
- 관리자 `pnpm.cmd exec tsc --noEmit`와 rich content blocks 대상 Chromium Playwright 1건을 통과했다. E2E는 저장 전 미리보기, 갤러리·사양 표·FAQ의 표시 순서와 PUT 문서를 확인한다.

### 미검증·후속

- 실제 사용자 페이지·자산에는 저장·발행·보관·삭제 요청을 보내지 않았다.
- gallery swipe gesture, 실제 390×844 브라우저 시각 확인과 페이지 유형/도메인 연결은 다음 단계에서 검증한다.

## 고객 메인 화면 상태 전환 모션

- AI 예약 도우미는 배경·패널·대화·추천 결과가 순서대로 나타나도록 했고, 검색 결과·선택 객실·예약 패널은 실제 상태 변경 때만 짧게 반응한다.
- 장식적인 페이지 진입·스크롤 애니메이션은 추가하지 않았다. `prefers-reduced-motion` 환경에서는 전환 시간을 사실상 제거한다.

### 검증

- 고객 웹 `pnpm.cmd build`를 통과했다.
- 로컬 고객 웹에서 AI 예약 도우미를 열고 닫아, 대화 입력·닫기 제어가 추가·제거되는 접근성 상태와 오버레이 표시를 확인했다.
- Impeccable detector는 기존 예약 패널의 굵은 상단 테두리 1건만 보고했다. 이번 모션 변경과 무관해 기존 레이아웃은 유지했다.

## 예약 바 지점 선택기

- 브라우저 기본 `select`를 지역·호텔명·선택 표시를 담은 맞춤 패널로 바꿨다. 예약 바의 색·테두리·여백과 맞추고, 모바일에서는 같은 한 열 흐름을 사용한다.
- 기존 지점 선택 시 해당 지점 랜딩으로 이동하는 동작은 `onChange`에 기존 함수를 그대로 전달해 유지했다.
- 트리거와 목록은 `listbox`/`option` 상태, Escape·바깥 클릭 닫기, 위·아래·Home·End 키 이동 및 Enter·Space 선택을 제공한다.

### 검증

- 새 키보드 순환 로직의 Node TypeScript 테스트를 먼저 실패시킨 뒤 통과시켰다.
- 고객 웹 `pnpm.cmd build`를 통과했다.
- 로컬 브라우저에서 패널의 현재 선택 표시와 설악산 선택 뒤 `/stays/seoraksan` 이동을 확인했다.

## 설악·제주 히어로 이미지와 문구 모션

- 설악산과 제주도 랜딩에 맞춘 16:9 히어로 이미지를 각각 생성해 고객 공개 CMS에 업로드하고 발행했다. 설악산은 `49235bbc-40a7-4452-88d0-cc35ef51e8b1`, 제주도는 `1dec6312-7309-4c87-8680-eb63bd2489a0` 미디어를 사용한다.
- 네트워크 또는 CMS 발행본을 사용할 수 없는 경우에도 동일한 지점 경험을 유지하도록 고객 웹의 정적 폴백을 `seoraksan-forest-hero.png`, `jeju-island-hero.png`로 지정했다.
- 히어로의 지역 문구·제목 각 줄·설명·예약 CTA는 지점 전환 시 한 번만 순서대로 안착한다. 텍스트를 완전히 숨기지 않고 이동·가벼운 blur만 사용해 즉시 읽을 수 있게 했으며, `prefers-reduced-motion`에서는 애니메이션을 제거한다.

### 검증

- `node --experimental-strip-types src/lib/content-page.test.ts`로 설악산·제주도 정적 폴백과 기존 미디어 경로 검증을 실행했다.
- `pnpm.cmd exec tsc -b`로 고객 웹 TypeScript 검사를 실행했다.
- 로컬 브라우저에서 설악산·제주도 공개 CMS가 각각 새 미디어 전달 경로를 사용하고, 제목 줄의 `hero-heading-line-in` 모션이 실행되는 것을 확인했다. 설악산은 모션 종료 뒤 opacity 1, blur 0, transform 원상복귀이며 콘솔 오류·가로 넘침이 없었다. 390×844에서도 제주도 제목은 보이고 가로 넘침이 없었다.
- 현재 환경에서는 Windows Application Control 정책이 일반 Vite/Rolldown의 `rolldown-binding.win32-x64-msvc.node` 로드를 차단한다. 같은 원인으로 기본 `pnpm.cmd build`와 `pnpm.cmd dev`가 번들링 전에 중단된다. 저장소 구성은 바꾸지 않고 호환 개발 서버로 브라우저 확인만 수행했다.

### 미검증·후속

- 위 보안 정책이 해제된 환경에서 기본 `pnpm.cmd build`를 다시 실행한다.
- 운영체제의 모션 감소 설정을 켠 실제 브라우저에서 히어로 문구가 즉시 표시되는지 한 번 더 확인한다.

## 상세 갤러리 스와이프

- 고객 상세 갤러리에서 좌우 48px 이상이고 세로 이동보다 큰 포인터 이동만 이미지 전환으로 해석한다. 왼쪽은 다음, 오른쪽은 이전 이미지로 순환한다.
- 이미지 영역은 `touch-action: pan-y`로 세로 스크롤을 유지한다. 제스처는 이미지 영역에서만 시작하며, 이전/다음 버튼과 썸네일의 기존 클릭·키보드 흐름에는 관여하지 않는다.

### 검증

- `gallery-swipe.test.ts`를 먼저 모듈 없음으로 실패시킨 뒤, 좌·우 스와이프·짧은 이동·세로 중심 이동의 판정 테스트를 통과시켰다.
- 고객 웹 `pnpm.cmd exec tsc -b`를 통과했다.

### 미검증·후속

- 현재 공개 고객 콘텐츠에 `IMAGE_GALLERY`가 없고 관리자 4001 서버도 내려가 있어, 실제 렌더러에서의 드래그 상호작용은 확인하지 못했다. 검증을 위해 실제 고객 페이지를 저장·발행하지는 않았다.

## 포레스트 갤러리 데모 콘텐츠

- 실제 고객 렌더러와 미디어 참조를 확인할 수 있도록 `/brand` 아래에 메뉴 비노출 `CONTENT_PAGE`인 `/brand/forest-gallery-demo`를 만들고 발행했다. 기존 공개 페이지와 메뉴 항목은 수정하지 않았다.
- 생성형 이미지 3장(객실·숲속 테라스·천연석 욕실)을 CMS 미디어 카탈로그에 업로드했다. HERO에는 객실 이미지를, `IMAGE_GALLERY`에는 세 자산을 순서대로 연결했고 이미지마다 개별 대체 텍스트와 캡션을 지정했다.
- 처음 실행 중이던 API 컨테이너는 이전 블록 allowlist라 `IMAGE_GALLERY`를 거부했다. 현재 소스로 API 이미지를 재빌드하고 readiness `UP`을 확인한 뒤 페이지를 생성·발행했다. 미디어 볼륨은 유지되어 업로드한 세 자산을 그대로 참조했다.

### 확인

- 공개 resolve API에서 `/brand/forest-gallery-demo`가 `CONTENT_PAGE`, `HERO` + `IMAGE_GALLERY`, 갤러리 이미지 3건으로 응답하고 공개 navigation에는 포함되지 않음을 확인했다.
- 로컬 고객 브라우저에서 HERO, 갤러리 제목·설명, 세 번째 이미지와 현재 위치, 이전/다음 버튼을 확인했다. 다음 버튼으로 순환 전환해 `3 / 3 → 1 / 3`, 첫 이미지의 대체 텍스트와 캡션을 확인했다.
- 실제 화면 포인터 동작의 판정 로직은 좌·우·짧은·세로 중심 이동 네 경우의 집중 테스트로 확인한다. 모바일 실기기 터치 제스처는 후속 확인 대상이다.

### 미검증·후속

- Windows Application Control이 기본 Vite/Rolldown 실행 파일을 차단하므로, 정책이 해제된 환경에서 표준 `pnpm.cmd build`와 실제 390×844 터치 스와이프를 다시 확인한다.

## 갤러리 방향 전환 모션

- 좌·우 스와이프 및 이전·다음 버튼이 바꾼 방향을 그대로 사용해, 새 사진은 이동 방향의 반대 가장자리에서 들어오고 현재 사진은 반대편으로 빠지게 했다. 두 이미지는 전환 중에만 함께 유지한다.
- 420ms의 `clip-path`·opacity·작은 transform·밝기 전환으로 사진의 경계와 깊이를 전달하고, 캡션·현재 위치는 짧게 이어진다. 전환이 끝나면 이전 레이어와 `will-change`를 바로 제거한다.
- 모션 감소 설정에서는 공간 이동·마스크·필터를 제거하고 120ms 교차 전환만 남긴다. 버튼·썸네일·키보드·기존 포인터 스와이프 판정은 유지했다.

### 검증

- 전환 helper를 먼저 없는 export로 실패시킨 뒤, 다음·마지막 순환·이전 순환의 index와 방향을 확인하는 집중 테스트를 통과시켰다.
- 고객 parser 테스트와 `pnpm.cmd exec tsc -b`를 통과했고, 변경 파일의 `git diff --check`도 통과했다.
- 로컬 고객 브라우저에서 다음 전환은 `forward`, 이전 전환은 `backward`를 기록했고, 전환 중 이미지 레이어 2장·종료 뒤 1장, 현재 위치·캡션의 갱신을 확인했다. 데스크톱 화면에서 갤러리 프레임·제어부·썸네일의 겹침은 없었다.

### 모바일·모션 감소 추가 검증

- 390×844 Chromium에서 가로 넘침 없이 갤러리 폭 351px와 이미지 안쪽 제어부를 확인했다. 모바일 캡처에서도 HERO·갤러리·썸네일·푸터가 한 열로 이어지고 겹치지 않았다.
- 모션 감소 에뮬레이션에서 처음에는 방향 선택자의 우선순위 때문에 420ms 이동이 남았다. 이를 재현한 뒤 축소 모션 선택자의 우선순위를 맞춰, 실제로 `gallery-image-fade-in` 120ms·transform 없음·filter 없음·현재 위치 갱신으로 동작함을 확인했다.

### 미검증·후속

- 실제 iOS·Android 기기에서 터치 포인터 스와이프의 체감과 운영체제 접근성 설정 연동은 후속 확인 대상이다.

## 관리자 상세 페이지 390px 미리보기

- 일반 콘텐츠 페이지 미리보기에 `데스크톱`과 `모바일 390px` 전환을 추가했다. 두 보기 모두 저장·발행 전 현재 편집 상태만 사용하며, 어떤 서버 변경 요청도 보내지 않는다.
- 모바일을 선택하면 독립된 390px 프레임 안에서 모바일 기본 여백·히어로·CTA·2열 갤러리 구성을 보여 준다. 프레임 밖은 중립 배경으로 남겨 실제 폭과 편집 화면을 구분한다.

### 검증

- `pnpm.cmd exec playwright test e2e/website-content-editor.spec.ts --grep "switches the content page preview to a 390px mobile frame|edits rich content blocks and previews them in customer order" --project=chromium`으로 모바일 전환과 기존 상세 블록 미리보기 2건을 통과했다.
- `pnpm.cmd exec tsc --noEmit`을 통과했다. 이전에는 Next 개발 서버가 만든 `.next/dev/types/routes.d.ts`가 중복 선언으로 손상되어 실패했으며, 관리자 개발 서버 재기동으로 생성 파일을 정상화한 뒤 재검증했다.
- 실제 관리자 `4001`에서 설악 포레스트 갤러리 데모의 데스크톱 폭 1009px와 모바일 폭 390px를 확인했다. 모바일 프레임의 `scrollWidth/clientWidth`는 모두 390px였다.
