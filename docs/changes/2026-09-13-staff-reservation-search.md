# 직원 예약 조회 화면

## 변경 이유

CMS의 현재 제품 범위를 완료한 뒤, 지점 직원이 당일 운영 화면으로 들어가기 전에 예약을 빠르게 찾고 숙박 정보를 확인할 수 있는 읽기 전용 예약 관리 화면이 필요하다.

## 구현 계획

- Spring Boot에 지점과 기준일을 필수 조건으로 하는 직원 예약 조회 API를 추가한다.
- 이름·이메일·예약 번호 검색과 예약 상태 필터를 지원한다.
- 관리자 화면에 예약 관리 메뉴를 추가하고, 달력·검색·상태 필터·예약 표·상세 대화상자를 한 화면에 배치한다.
- 조회는 최대 200건으로 제한하고 객실 유형·숙박일 인덱스를 추가해 운영 데이터 증가에 대비한다.
- 기존 직원 세션과 지점 접근 권한, 공통 UI 컴포넌트를 재사용한다.

## 완료 기준

- 지점 권한이 적용된 예약만 기준일에 맞게 조회된다.
- 이름·이메일·예약 번호 검색과 상태 필터가 함께 동작한다.
- 키보드로 예약 행을 선택해 상세 대화상자를 열고 닫을 수 있다.
- 모바일에서도 핵심 열과 상세 열기, 검색 기능을 사용할 수 있고 데스크톱에서는 전체 표를 확인할 수 있다.
- 변경한 API 통합 테스트, 관리자 타입 검사·빌드, 핵심 UI 상호작용 검증이 통과한다.

## 이번 범위에서 제외

- 예약 생성·변경·취소
- 객실 배정·체크인·체크아웃 등 기존 당일 운영 액션의 이동
- 월별 통계, CSV 내보내기, 대량 작업

## 호환성과 롤백

- V28은 기존 데이터를 변경하지 않는 인덱스 추가 migration이며 이전 API·writer와 함께 동작한다.
- 애플리케이션 롤백 뒤 인덱스가 남아 있어도 동작에는 영향이 없다. 완전 롤백이 필요하면 별도 점검 후 `DROP INDEX reservation_staff_stay_search_idx`를 실행한다.

## 검증 결과

- `StaffOperationsIntegrationTest` 12건이 PostgreSQL 테스트 DB에서 통과했다. 기준일·출발일 포함·대소문자 없는 고객 검색·부분 예약 번호·상태·200건 상한과 HTTP 응답·필수 날짜·타 지점 403을 확인했다.
- Flyway V28을 테스트 DB에 적용해 기존 27개 migration과 새 조회 인덱스의 호환성을 확인했다.
- 관리자 변경 파일 ESLint는 오류·경고 없이 통과했고 Next.js production build는 `/dashboard/reservations`를 포함한 정적 경로 104개를 생성했다.
- 예약 관리 Playwright 1건에서 지점 직원 세션, 상태와 검색어의 동시 전달, 키보드 상세 열기·Escape 닫기·초점 복귀, 390×844 핵심 컨트롤 노출을 확인했다.
- 실제 관리자 화면에서 데스크톱 달력·필터·표의 배치와 접근성 트리를 확인했다. 개발 API 4080은 이번 브랜치로 재빌드하지 않아 실제 개발 데이터 조회는 수행하지 않았다.
