# 고객 요청 감사 통합·XLSX 내보내기

## 변경 이유

고객 요청은 상세 화면 안에서만 생성·상태 변경 이력을 볼 수 있었고 담당자·우선순위 변경은
시점별 값이 남지 않았다. 본사 감사 화면에는 이 이력이 없었으며 CSV 외에 실제 Excel 파일을
내려받을 수 없었다. 기존 개인정보 마스킹, 최신순 조회, 페이지와 CSV 열 계약을 유지하면서
고객 요청의 처리 책임과 변화 과정을 한 화면에서 확인하도록 확장했다.

## 구현 내용

- V66이 `guest_request_event`에 이전/이후 담당자와 우선순위 스냅샷을 추가하고
  `PRIORITY_CHANGED` 이벤트를 허용한다. 전사 감사 최신순 조회를 위한
  `(created_at DESC, id DESC)` covering index와 직원 변경 명령 멱등 영수증 표도 추가했다.
- 고객 요청 변경은 요청 행을 `FOR UPDATE`로 잠그고 같은 요청의 동시 변경을 직렬화한다.
  같은 멱등 키·같은 본문은 기존 결과를 반환하고 같은 키·다른 본문은 409로 거부한다.
  담당자는 활성 본사 관리자 또는 요청 지점의 활성 지점 직원만 지정할 수 있다.
- V67은 변경 이벤트에 직원 행위자와 서로 다른 전후값이 반드시 존재하도록 DB CHECK를 추가한다.
  감사 count와 목록은 `REPEATABLE_READ` 읽기 전용 트랜잭션에서 같은 snapshot을 사용한다.
- 한 요청에서 담당자·우선순위·상태가 함께 바뀌면 각각 `ASSIGNED`,
  `PRIORITY_CHANGED`, `STATUS_CHANGED` 이벤트를 남긴다. 생성 이벤트는 고객 행위자와 생성 당시
  기본 우선순위를 명시한다. 현재 요청 행으로 과거 값을 추정하거나 기존 이력을 소급 생성하지 않는다.
- 통합 감사 조회에 `GUEST_REQUEST_EVENT`를 추가했다. 생성 고객은 `CUSTOMER`, 직원 변경은 실제
  직원 역할로 표시한다. 요약은 요청 ID 일부, 요청 유형, 상태·담당자·우선순위 enum/표시명만 쓰고
  제목·본문·연락처·처리 메모는 넣지 않는다.
- 모든 UNION 원본 UUID를 숨은 정렬키로 투영해 `created_at DESC, event_type, source_event_id`로
  정렬한다. 같은 시각의 이벤트도 페이지 간 중복·누락 없이 결정적인 순서를 갖는다.
- `GET /api/staff/audit/export.xlsx`가 현재 조회와 같은 필터·마스킹·limit·offset을 사용해
  화면의 현재 페이지를 내보낸다. CSV와 동일한 10개 열·순서·한국어 유형명을 사용하고
  `Cache-Control: no-store`와 다운로드 파일명을 제공한다.
- CSV와 XLSX 모두 `=`, `+`, `-`, `@`로 시작하는 값을 텍스트로 정규화한다. XLSX는 모든 값을
  명시적인 문자열 셀로 기록한다.
- 관리자 페이지의 페이지 번호를 실제 행 offset으로 변환해 2페이지가 `offset=20`을 요청하게
  고쳤고 서버 최대 offset을 넘는 페이지를 노출하지 않는다. 고객 요청 유형명, 고객 행위자,
  XLSX 버튼을 추가하고 390px에서도 조작 가능하게 유지했다. 고객 요청 상세도 담당자·우선순위
  이벤트를 빈 상태 전환으로 표시하지 않고 각 전후값을 보여준다.

## 검증 결과

- `GuestRequestIntegrationTest` 28건 통과: 담당자·우선순위·상태 독립 이벤트, 상태 유지 단독 변경,
  완전 no-op 영수증, 유효하지 않은 우선순위·타 지점 담당자의 전체 롤백, 담당자 비활성 후 멱등 재호출,
  같은 키의 다른 본문 409, 기존 조회·권한·페이지 계약을 확인했다.
- `AuditIntegrationTest`, `AuditEventsXlsxServiceTest` 21건 통과: 고객 생성·담당자·우선순위·상태
  네 이력, 고객/직원 행위자, 자유 입력·연락처 비노출, 마스킹, 필터·최신순·페이지, 실제 OOXML,
  동일 시각 페이지 무중복, 조회 전후 행 불변, CSV 호환 10개 열과 문자열 셀·수식 접두 방어를 확인했다.
- 관리자 `audit.spec.ts` 12건과 `guest-requests.spec.ts` 7건, Chromium 총 19건 통과:
  한국어 유형명, 고객/직원 행위자와 요청 요약, 상세 담당자·우선순위 전후값, `offset=20`, 마스킹 유지,
  CSV BOM/내용과 수식 방어, 현재 페이지 XLSX 쿼리·파일명, 390px 문서 폭과 버튼을 확인했다.
- TypeScript 검사와 API 컴파일이 통과했다. 전체 ESLint는 설정이
  `react-hooks/set-state-in-effect` 규칙을 선언하면서 `react-hooks` 플러그인을 등록하지 않아
  코드 검사 전에 종료 코드 2로 실패했다. 이번 변경에서 발생한 lint 진단은 아니다.
