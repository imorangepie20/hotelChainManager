# 운영 대시보드 실제 데이터 연결과 예약 화면 복구

## 변경 이유

관리자 첫 화면이 실제 예약·객실 데이터 대신 준비 상태 문구만 보여주고 있었다. 또한 운영 통계용 테스트 샘플의 승인 대기 요청에는 견적이 없어서, 본사 계정이 `/dashboard/reservations`를 열면 `differenceKrw` null 접근으로 전체 화면이 오류 경계에 빠졌다.

현재 배포 대상과 DB는 실제 운영이 아닌 테스트 환경이다. 따라서 별도 백업 없이 반복 실행 가능한 샘플 SQL을 적용하되, 저장소에는 비밀값이나 DB 덤프를 남기지 않는다.

## 구현

- `/dashboard/default`는 `GET /api/staff/hotels/{hotelId}/operations`를 서울 오늘 날짜로 조회한다.
- 본사는 속초·설악산·제주의 도착, 출발, 객실 배정 필요, 청소 필요 건수를 한 화면에서 비교한다.
- 지점 직원은 자기 지점만 조회하며 실제 업무 카드와 오늘의 운영 화면 링크를 본다.
- 조회 실패 시 전체 화면을 깨뜨리지 않고 오류 안내와 다시 시도 버튼을 제공한다.
- 테스트 샘플 SQL은 지점마다 오늘 도착 1건, 출발 1건, 미배정 도착 1건, 청소 필요 객실 1개가 나오도록 실제 객실과 배정을 멱등하게 추가한다. UI에서 샘플 배정을 바꾼 뒤 다시 실행해도 지정 상태로 복원한다.
- 샘플 변경 요청에는 0원 차액 견적과 일별 금액을 연결해 승인 대기 요청이 정상 검토 가능한 도메인 상태를 유지한다.
- 예약 변경 응답의 `quote`가 null일 수 있음을 타입에 반영했다. 승인 대기 표와 진행 중 변경 패널은 금액 대신 `금액 정보 없음`을 표시하고, 견적 없는 요청의 검토 버튼을 비활성화한다.

## 미검증·제약

- `npm run lint`는 변경 코드가 아니라 ESLint flat config의 `react-hooks/set-state-in-effect` 규칙에 플러그인이 연결되지 않은 기존 구성 오류로 실행되지 않았다.
- 테스트 샘플의 견적 없는 승인 요청은 실제 업무 데이터로 승인할 수 없도록 비활성화한다. 필요하면 별도 샘플 견적을 추가해야 한다.
