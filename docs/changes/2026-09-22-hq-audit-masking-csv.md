# 본사 감사 이력 - 개인정보 마스킹·CSV 내보내기 (2026-09-22)

> 상태: 작업 트리에만 있고 커밋하지 않은 상태.

## 변경 이유

`admin-menu-roadmap.md` 7번 `감사·이력 조회`의 남은 항목 중 "개인정보 마스킹 옵션"과 "CSV·Excel 내보내기"를 구현했다. 감사 이력은 처리 추적을 위해 고객 이름·이메일을 보여주는데, **본사가 화면을 공유하거나 캡처할 때 개인정보가 그대로 퍼졌다.** 내보내기도 없어서 이력을 전달하려면 화면을 찍어야 했다.

## 서버 변경

- `GET /api/staff/audit?masked=true`가 고객 이름·이메일을 가린다. 응답의 `masked` 필드로 현재 상태를 알려준다. 기본값은 `false`이고, 생략하면 기존과 같이 원래 값이 내려온다.
- **식별자는 가리지 않는다.** 예약 id, 객실 번호, 금액, 처리 직원의 이메일·이름·역할은 그대로 둬서 "누가, 언제, 무엇을 바꿨는지"는 추적할 수 있게 뒀다. 고객 개인정보만 가리는 것이 목적이기 때문이다.
- `GUEST_UPDATE`의 `summary`는 `이전 예약자 홍길동 / old@example.com → 김철수 / new@example.com` 형태라 **요약 안에도 이름·이메일이 중복으로 들어 있다.** 그래서 요약도 같이 가린다. 다른 유형의 요약에는 고객 개인정보가 없으므로 그대로 둔다.
- 이메일 도메인(`@example.com`)은 가리지 않는다. 개인을 식별하지 못하는 부분이고, 도메인이 있어야 발송처를 파악할 수 있기 때문이다.
- `PiiMasker`는 이름의 마지막 한 글자만 남기고 나머지를 `*`로 채운다. 1글자 이름은 전체를 가린다. 이메일은 로컬 파트만 같은 규칙을 적용한다.
- `HQ_ADMIN`만 호출 가능하고 지점 직원은 403, 잘못된 세션은 401이다. 마스킹 여부와 무관하게 권한은 같다.
- **SELECT만 사용**하고 상태를 변경하지 않는다. 마이그레이션도 필요 없다.

## 관리자 UI 변경

- `감사 이력` (`/dashboard/audit`)에 `개인정보 마스킹` 토글과 `CSV 내보내기` 버튼을 추가했다.
- 토글을 켜면 마스킹 안내(`audit-masked-notice`)를 보여주고, 첫 페이지로 돌아가서 다시 불러온다. 토글이 켜진 상태에서 페이지를 옮겨도 마스킹이 유지된다.
- **CSV는 브라우저에서 파일로 내려준다. 서버를 거치지 않는다.** 매개변수 조작이나 헤더 주입이 없다.
- CSV 파일 이름에 마스킹 상태를 표시한다(`audit-events-masked-0.csv`). 마스킹이 켜진 상태에서 내보내면 가려진 값이 그대로 파일에 들어간다.
- CSV에는 UTF-8 BOM을 붙였다. BOM이 없으면 엑셀이 한글을 깨져서 보이기 때문이다.

## 검증 결과

- API `mvnw -Dtest=AuditIntegrationTest` **16건**(기존 12 + 신규 4)이 종료 코드 0이다. 새 검증은 마스킹 200 `masked=true`·이름 가림·요약의 `**` 포함·도메인 유지·`masked=false` 원문 복원·객실 번호·처리 직원 유지·지점 직원 403이다.
- 관리자 `tsc --noEmit`이 종료 코드 0이고, `eslint`는 경고만 낸다(`react-hooks/set-state-in-effect`, 기존 컴포넌트와 같은 패턴).
- Playwright `audit` **9건**(기존 7 + 신규 2)이 종료 코드 0이다. 새 검증은 토글이 `masked=true` 요청을 보내는지와 CSV 다운로드의 내용이 헤더·유형 라벨·처리 직원·요약을 모두 포함하는지다.

## 발견·수정한 결함

1. `mapEvent`를 새 메서드 추가 과정에서 실수로 지워서 `invalid method reference` 컴파일 오류가 났다. 즉시 복구했다.
2. 첫 마스킹 테스트에서 `guestName`이 `*****`일 것이라고 단정했다. 실제로는 `audit-guest`가 10글자라 `**********t`가 내려왔다. 마스킹 규칙 자체는 맞았고, 단정이 틀렸다. 원문과 다르고 마지막 글자가 남는지로 바꿨다.

## 미검증 항목

- 라이브 DB·compose `api` 재빌드·브라우저 확인은 실행하지 않았다. 라이브 감사 데이터에서 마스킹이 올바르게 적용되는지, CSV가 엑셀에서 한글이 깨지지 않는지는 사용자가 확인한다.
- **Excel(xlsx) 내보내기는 이번 범위가 아니다.** CSV는 텍스트 편집기·엑셀 모두 열 수 있지만 `.xlsx` 이진 형식은 아니다.
- **마스킹은 옵션이지 기본값이 아니다.** 기본은 여전히 원문 노출이다. 규정상 마스킹이 항상 필요하면 기본값을 바꿔야 하는데, 그러면 처리 건을 추적하기 어려워진다. 정책 결정이 필요하다.
- **마스킹은 표시 영역만 가린다.** 데이터베이스의 원본 값은 그대로고, 본사 세션이 있으면 `masked=false`로 원문을 다시 볼 수 있다. 접근 권한 자체를 제한하는 것은 아니다.
- 고객 요청 이력(6번 메뉴와 겹침)은 6번 메뉴를 구현할 때 다시 다룬다.
