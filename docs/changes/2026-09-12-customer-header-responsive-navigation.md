# 고객 헤더 반응형 내비게이션 수정

## 요청과 원인

고객 설악산 페이지의 약 1186px 화면에서 상단 메뉴가 한두 글자 단위로 줄바꿈되는 문제가 확인됐다. 헤더는 메뉴 링크의 줄바꿈을 허용한 상태에서 고정 38px 간격과 900px 모바일 전환점만 사용하고 있었다. 브라우저 측정 결과 한국어 메뉴 9개의 텍스트 줄 상자가 모두 2개였고, flex 축소 과정에서 한글의 글자 사이 줄바꿈이 발생했다.

## 변경

- 데스크톱 메뉴 링크, 브랜드, 예약 조회와 언어 선택을 한 줄로 유지한다.
- 데스크톱 메뉴 간격은 `clamp()`로 가용 폭에 따라 줄어든다.
- 전체 메뉴를 펼치기 어려운 1100px 이하에서는 헤더만 기존 메뉴 버튼과 세로 메뉴로 전환한다.
- 다른 예약·콘텐츠 레이아웃의 기존 900px 반응형 규칙은 변경하지 않았다.
- 데스크톱 우측의 `예약 조회`와 현재 언어 표시를 동일한 44px 높이와 하단 테두리 방식으로 통일해 밑줄 기준선이 어긋나지 않게 했다.

## 검증

- 1186px 한국어 메뉴 9개가 각각 한 줄이고 문서 가로 오버플로가 없는 Playwright 회귀 테스트를 추가했다.
- 1024px에서 전체 메뉴를 숨기고 메뉴 버튼을 표시한 뒤, 버튼으로 9개 링크의 세로 메뉴를 열 수 있으며 가로 오버플로가 없는 회귀 테스트를 추가했다.
- 실제 고객 설악산 페이지 1186px에서 메뉴 9개의 줄 상자가 모두 1개이고 가로 오버플로가 없음을 확인했다.
- 고객 헤더 관련 Playwright 4건이 통과했다: 영문 CMS 1280px·390px, 한국어 헤더 1186px·1024px.
- 1440px에서 `예약 조회`와 현재 언어의 높이·하단 기준선·표시 방식을 비교하는 회귀 테스트를 추가했다. 수정 전 8px 오차로 실패하고 수정 후 1px 이내 기준으로 통과했다.
- 390px 캡처에서 브랜드·언어 선택·메뉴 버튼이 겹치지 않는 것을 확인했다.
- 고객 production build가 통과했다. TypeScript 검사와 Vite 빌드에서 2,898개 모듈을 변환했다.
- `git diff --check`가 통과했다.

실제 모바일 기기 Safari·Chrome 검증은 수행하지 않았다.
