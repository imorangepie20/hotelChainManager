# 직원 접근 기반 변경 기록

## 구현 내용
- Flyway V6에 `staff_member`, `staff_session` 테이블을 추가했다.
- 직원 비밀번호는 BCrypt 해시로, 세션 토큰은 SHA-256 해시로만 저장한다.
- `HQ_ADMIN`은 모든 지점에, `BRANCH_STAFF`는 소속 지점에만 접근하도록 `StaffAccessService`에서 검사한다.
- 로그인, 현재 세션 확인, 로그아웃, 지점 권한 확인 API를 추가했다. 고객 예약의 `X-Reservation-Token` 흐름은 변경하지 않았다.
- 개발 프로필에서만 환경 변수로 받은 비밀번호를 BCrypt 해시해 본사·3개 지점 계정을 초기화한다. `.env.example`은 값 형식만 제공하며 실제 비밀번호는 저장하지 않는다.
- 관리자 루트 경로는 로그인 화면으로 이동하며, 로그인 성공 시 세션 토큰과 직원 정보를 브라우저 저장소에 기록한 후 운영 대시보드로 이동한다. Next.js는 `/api` 요청을 4080 API로 프록시한다.
- 로그인 화면과 본사·속초 운영 화면 전환 E2E를 추가했다.
- 본사 계정에는 전체 컨텍스트를, 지점 직원에게는 소속 호텔 컨텍스트만 표시하도록 대시보드를 제한했다.
- 대시보드 레이아웃은 세션 토큰과 직원 정보가 없으면 로그인 화면으로 이동한다. 이 단계의 브라우저 진입 검사는 화면 보호용이며, 서버 세션 재검증은 다음 단위에서 추가한다.
- 대시보드 진입 시 `/api/staff/me`으로 세션을 재검증하고 서버가 거부하면 로그인으로 이동한다. 헤더 로그아웃은 서버 세션 폐기를 요청한 뒤 브라우저 저장소를 비운다.

## 검증
- `mvnw.cmd -q -Dtest=StaffAccessIntegrationTest test` 통과.
- 속초 직원의 제주 접근 거부와 본사 계정의 제주 접근 허용을 PostgreSQL 통합 테스트로 확인했다.
- `staff-login.spec.ts`, `hotel-operations-overview.spec.ts` E2E 2개 통과.
- 속초 직원이 본사·제주 컨텍스트를 볼 수 없고 속초가 선택되는 E2E를 통과했다.
