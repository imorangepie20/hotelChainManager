# 전체 CMS 영문 번역·발행

## 요청과 범위

사용자가 속초 지점에 이어 나머지 페이지도 모두 번역해 영문 발행하도록 명시적으로 요청했다. CMS 트리에 있는 편집 가능한 페이지 7개를 대상으로 했으며, 구조 전용 `SECTION`인 숙소·브랜드는 번역 문서를 갖지 않으므로 대상에서 제외했다. 기존 이미지·경로·메뉴 순서와 노출 여부·기간·체크인/체크아웃 시각·페이지 연결은 유지했다.

## 실제 발행

- 홈: `/en`
- 지점: `/en/stays/sokcho`, `/en/stays/seoraksan`, `/en/stays/jeju`
- 브랜드: `/en/brand/story`, `/en/brand/haneul-story`, `/en/brand/forest-gallery-demo`

각 페이지의 메뉴 이름, SEO, 히어로, 본문 또는 지점 경험·오퍼·도착 안내, 이미지 alt와 갤러리 캡션을 영어로 번역했다. 예약 화면은 아직 한국어라는 현재 제품 경계를 CTA 문구에 명시했다. 갤러리 데모는 기존 메뉴 비노출 설정을 유지했으므로 영문 URL로 직접 접근할 수 있지만 상단 메뉴에는 나타나지 않는다.

`하늘의 이야기` 한국어 초안 두 번째 문단에는 첫 문장이 여러 차례 반복되어 있었다. 영문 초안에서는 같은 의미를 반복하지 않고 자연과 일상 사이의 균형을 이어 설명하는 한 문단으로 번역했다. 한국어 원문은 변경하지 않았다.

## 영문 홈 공개 오류 수정

영문 홈 발행 직후 공개 API는 `HOME_PAGE`와 발행 콘텐츠를 정상 반환했지만 고객 `/en`은 미발행 안내를 표시했다. 고객 홈 분기가 응답의 `content`만 파서에 전달해 `contentKind`, 연결 정보와 문서 형식을 잃었고, 실제 발행 블록의 `blockId`를 레거시 문서가 거부하는 것이 원인이었다.

- 고객 홈도 공개 응답 전체를 파서에 전달한다.
- 파서는 `contentKind=HOME`인 공개 문서를 block ID가 포함된 발행 형식으로 읽는다.
- 다른 상세 콘텐츠 유형의 parser 계약과 백엔드·DB·발행본은 변경하지 않았다.

## 검증

- TDD RED: 실제 응답 형태의 영문 홈 fixture를 `/en`에서 렌더링하는 Chromium E2E가 제목을 찾지 못해 실패하는 것을 확인했다.
- GREEN: 고객 영문 CMS E2E 1280px·390px 2건 통과.
- 고객 `cms-locale`, `customer-route`, `content-page`, `content-collection` 직접 테스트 4건 통과.
- 고객 production build 통과: TypeScript와 Vite 빌드, 2,898개 모듈 변환 완료.
- 실제 브라우저에서 `/en`의 SEO 제목·영어 메뉴·히어로·본문·CTA를 확인했다.
- 실제 브라우저에서 속초·설악산·제주와 브랜드 이야기·하늘의 이야기·설악 갤러리의 영문 제목·본문·이미지 alt를 확인했다. 갤러리는 첫 이미지와 캡션, 이전/다음 조작 노출을 확인했다.

코드 변경은 고객 홈 파서 경로와 해당 회귀 테스트뿐이다. 백엔드 migration·API 재빌드와 예약/결제/AI 전체 영어화는 수행하지 않았다.
