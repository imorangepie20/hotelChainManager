# 예약 상세 미배정 객실 배정

## 변경 이유

직원이 예약을 조회한 뒤 별도 당일 운영 화면으로 이동하지 않고도 확정 예약에 남은 실제 객실을 배정할 수 있어야 한다.

## 구현 범위

- 예약 상세의 `CONFIRMED` 예약에서 배정 객실 수가 예약 객실 수보다 적을 때만 객실 배정 기능을 표시한다.
- 기존 배정 가능 객실 조회와 객실 배정 API를 그대로 사용한다.
- 다객실 예약은 남은 객실을 한 실씩 배정하고, 성공할 때마다 상세를 닫은 뒤 목록을 다시 조회한다.
- 조회·배정 오류는 상세 안에 표시하며 선택한 객실로 다시 시도할 수 있다. 동일 예약·동일 객실 재요청은 기존 배정을 성공으로 처리한다.

## 완료 기준

- 서버가 반환한 동일 지점·객실 유형·청결·숙박 기간 조건의 후보만 선택할 수 있다.
- 배정 요청은 기존 직원 세션과 서버의 지점 권한·예약 상태·중복 배정 검증을 거친다.
- 모바일과 키보드에서 후보 조회, 선택, 오류 확인, 재시도와 성공 결과 확인이 가능하다.
- 모든 객실이 배정되면 상세의 추가 배정 기능을 표시하지 않는다.

## 제외 범위

- 기존 배정 객실 변경·해제
- 날짜·객실 유형·요금제·인원·가격·결제 변경
- 체크인·체크아웃·노쇼 처리 위치 변경
- DB migration과 서버 API 변경

## 검증 결과

- `StaffOperationsIntegrationTest` 14건이 통과했다. 체크인 뒤 동일 예약·동일 객실 재호출이 충돌이나 중복 행 없이 완료되고, 후보 조회 뒤 청결 상태가 바뀐 객실은 최종 배정에서 거부되는 회귀를 포함한다.
- 예약 관리 Chromium E2E 3건이 통과했다. 부분 배정된 2실 예약의 후보 조회, 모바일 키보드 선택, 응답 유실 뒤 동일 객실 재시도, 성공 후 목록 재조회와 완전 배정 상태를 확인했다. 상세의 두 편집 폼과 오류가 함께 열린 상태에서도 390×844 viewport 안에 머물며 Tab으로 하단 예약 취소까지 도달한다.
- 변경 프런트 파일 ESLint와 UI detector가 통과했다.
- Next.js production build가 `/dashboard/reservations`를 포함한 정적 페이지 104개를 생성했다.
