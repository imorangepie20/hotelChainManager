# 체크인 전 예약 일정·객실 유형 변경

## 변경 이유

직원이 체크인 전에 확정 예약의 숙박 날짜 또는 객실 유형을 바꾸되, Spring Boot가 최신 일별 재고와 요금을 다시 확정해야 한다.

## 구현 계획

1. 직원 전용 변경 미리보기에서 현재 예약이 점유한 재고를 반영해 가능한 객실 유형·요금제와 최신 일별 요금·총액 차이를 계산한다.
2. 변경 확정 시 예약과 기존·신규 재고 행을 일정한 순서로 잠그고, 기존 확정 재고 반환과 신규 확정 재고 확보, 예약·일별 요금 갱신, 감사 기록을 한 트랜잭션에서 수행한다.
3. 예약 상세에 날짜 입력, 변경안 조회, 객실 유형 선택, 가격 차이 확인과 명시적 저장 흐름을 기존 대화상자 안에 추가한다.
4. 서버 통합 테스트와 관리자 E2E·타입·빌드 검사를 실행하고 실제 예약 관리 화면을 데스크톱과 모바일 크기에서 확인한다.

## 완료 기준

- `CONFIRMED`이며 지점 현지 날짜가 기존 체크인일보다 이른 미배정 예약만 변경할 수 있다.
- 본사 관리자 또는 예약 지점 직원만 조회·변경할 수 있고, 다른 지점과 체크인일 도달·배정 완료·확정 이외 예약은 변경되지 않는다.
- 서버가 객실 유형·요금제 관계, 동일 지점, 수용 인원, 전 숙박일 재고와 최신 요금을 검증한다.
- 기존 재고 반환, 신규 재고 확정, 예약 일정·객실 유형·요금제·총액과 `reservation_night` 교체, 감사 이력이 모두 성공하거나 모두 롤백된다.
- 같은 직원·요청의 멱등 재시도는 최초 결과를 반환하고, 같은 키의 다른 요청이나 다른 직원 요청은 충돌한다.
- UI는 최신 서버 견적과 이전·신규 총액 차이를 표시하고, 입력 변경 시 이전 견적과 요청 키를 폐기한다.

## 범위 제한

- 객실 수와 투숙 인원은 변경하지 않는다.
- 배정된 실제 객실을 자동 해제하거나 다시 배정하지 않는다.
- 실제 추가 결제·부분 환불은 구현하지 않는다. 현재 테스트 결제 범위에서는 예약 총액을 최신 서버 요금으로 갱신하고 차액과 처리 직원을 감사 이력에 남긴다.
- 고객 직접 변경, 알림 발송, 체크인 당일 예외 승인과 역할별 금액 승인 단계는 포함하지 않는다.

## 검증 결과

- `StaffReservationStayChangeIntegrationTest` 7건이 통과했다. 날짜·객실 유형 변경, 일별 요금·총액·감사, 겹치는 날짜의 자기 재고 보정, 일부 날짜 품절과 가격 변경의 전체 롤백, 직원 포함 멱등 재시도, 상태·지점·체크인일·배정 객실·수용 인원 제한, 본사 처리와 HTTP 계약을 확인했다.
- 예약·취소·직원 운영 회귀를 포함한 백엔드 대상 테스트 54건이 통과했다.
- 예약 관리 Chromium E2E 6건이 통과했다. 390×844에서 날짜 입력, 견적 폐기·재조회, 객실 유형 선택, 가격 차이와 테스트 결제 안내, 응답 유실 뒤 동일 키 재시도, 성공 후 목록 갱신 및 기존 예약 관리 흐름을 확인했다.
- 변경 프런트 파일 ESLint가 통과했다. production build는 예약 관리 E2E의 격리된 4101 서버 기동 과정에서 성공했다.
- 현재 작업 트리의 관리자 웹을 4001 포트로, Spring Boot API를 4080 포트로 다시 빌드해 실행했다. 체크인 전 확정 예약 상세에서 실제 재고·최신 요금 변경안과 금액 차이가 표시되는 것까지 브라우저로 확인했다. 실제 저장은 실행하지 않아 개발 DB의 예약은 변경하지 않았다.

## 미검증·후속 범위

- 실제 PG의 추가 결제·부분 환불, 승인 금액 한도, 고객 알림과 고객 직접 변경은 검증하지 않았다.
- 배정 객실이 있는 예약은 변경하지 않으며 자동 해제·재배정과 체크인 당일 예외 승인은 후속 정책이 필요하다.
- 운영 배포와 다중 인스턴스 장기 부하 검증은 수행하지 않았다.
