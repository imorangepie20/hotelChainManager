# 의사결정



## 사용자 확정 사항

- 2026-09-10: 국내 3개 지점 위치를 속초·설악산·제주도로 확정했다. 속초와 설악산은 별도 지점으로 관리한다.

- 관리자 디자인은 제공된 `SDTPL_ADM/` 테마와 `http://localhost:2455/dashboard` 프로젝트를 함께 참고한다. 본사·지점 관리자에 적용하며, 참조 프로젝트는 디자인 참고 범위로 사용한다.

- 참조 대시보드 시각 확인: 밝은 회색 바탕, 흰색 카드, 얇은 경계선과 둥근 모서리, 작은 보조 설명과 큰 수치, 작은 선형 아이콘, 차트·상태 중심의 강조색을 관찰했다. 구현 방향은 SDTPL_ADM의 기능성 컴포넌트를 유지하면서 해당 시각 스타일을 반영하고, 본사는 지점 비교·매출·점유율, 지점은 당일 예약·객실·청소 중심으로 배치하는 것이다. 정확한 디자인 토큰과 모바일 화면은 미측정이다.

- 호텔 고객 웹·예약·운영·AI 예약 도우미를 하나의 프로젝트로 개발한다.

- 제공된 `harness/`를 작업 방식의 기준으로 사용한다.

- `SDTPL_ADM/`은 관리자 UI·디자인용이며 수정 가능하다.

- 2026-09-10: 사용자 지시에 따라 프로젝트 초기화 작업을 시작했다.

- 2026-09-10: 개발 포트는 고객 웹 `4000`, 관리자 `4001`, API `4080`, AI `9000`으로 확정했다. 실행 환경 구성 시 적용한다.

- 2026-09-10: 비회원 예약 관리 토큰은 브라우저가 32바이트 난수로 생성하고 서버는 해시만 저장한다. 예약 생성은 토큰 해시와 멱등 키 조합으로 중복을 방지한다.



## 제안한 설계와 기본값

- Spring Boot 모듈형 단일 애플리케이션과 별도 AI 서비스를 사용한다.

- 한 지점 예약 흐름부터 연결한 뒤 운영·다지점·AI·다국어로 확장한다.

- 임시 재고 확보는 10분을 제안한다. 아직 제품 정책으로 검증하지 않았다.
- 2026-09-11: 고객 웹의 페이지·경로·메뉴·콘텐츠 발행 기준은 `website_page`로 둔다. 기존 `hotel_web_content`의 호텔 1:1 문서는 삭제하지 않고 이관 원본과 기존 API 호환 facade로 유지한다. 이 선택은 지점 랜딩 외의 브랜드·캠페인·하위 페이지를 추가할 때 URL 유일성·페이지별 버전·메뉴 발행을 한 문서에서 보장하기 위한 것이다.
- 2026-09-11: V10의 첫 일반 페이지 유형은 `CONTENT_PAGE` 하나로 제한한다. `SECTION`의 직계 자식만 생성하고 `hotel_id`는 항상 `NULL`로 둔다. 이 범위에서 페이지 이동·삭제·중첩·드래그 앤 드롭을 제외해 URL·메뉴·발행 버전 계약을 단순하게 유지한다.
- 2026-09-11: 일반 페이지 문서는 `seo`와 `HERO`·`TEXT`·`CTA` allowlist 블록만 허용한다. HTML/Markdown/스크립트·원격 이미지·외부 CTA를 저장하거나 렌더링하지 않으며, CTA는 `/`, `/#fragment`, 또는 안전한 로컬 경로만 사용한다. 서버 validator와 고객 웹 parser가 각각 이 제약을 적용한다.
- 2026-09-11: 일반 페이지의 생성·초안 저장·발행·버전 조회는 page ID API로 통일하고 `HQ_ADMIN`만 실행한다. 저장·발행은 양의 낙관적 버전을 요구하고, 경로·메뉴·콘텐츠를 같은 초안/발행 스냅샷으로 관리한다. 기존 `HOTEL_LANDING` facade는 호환성을 위해 유지한다.
- 2026-09-11: 홈페이지는 `CONTENT_PAGE`의 루트 확장이 아니라 단일 `HOME_PAGE`로 분리한다. 홈의 `hotel_id`·`parent_id`는 `NULL`, 경로는 `/`, slug는 `home`, 메뉴 노출은 `false`로 고정하고 공개 navigation에서는 제외한다. 이 선택으로 일반 페이지의 `SECTION` 직계 제약과 메뉴 계약을 유지한다.
- 2026-09-11: 홈페이지의 저장·발행·버전 조회는 본사 전용 home API로만 처리한다. 저장 요청은 콘텐츠와 초안 버전만 받고 서버가 고정 메타데이터를 적용하며, 일반 page publish API는 `HOME_PAGE`를 거부한다. 고객 화면에서는 CMS가 히어로·본문·CTA만 소유하고 예약 검색·AI·가격·재고·결제는 기존 코드와 Spring API가 계속 소유한다.
- 2026-09-11: 고객 CMS 이미지는 자유 URL이 아니라 `website_media_asset` UUID로 참조한다. 기본 내장 자산은 현재 고객 웹에서 실제 쓰는 속초 해안 PNG 한 건이며 UUID `14000000-0000-0000-0000-000000000001`로 고정한다. 다른 root Gemini 이미지는 브랜드 문구가 맞지 않아 등록하지 않는다.
- 2026-09-11: 업로드 이미지는 Compose `hotel-media-data` named volume에 UUID 키로 보관하고 `/api/website/media/{id}/content`에서 공개 전달한다. 카탈로그·업로드·사용 위치 조회는 `HQ_ADMIN`만 할 수 있으며, 서버가 실제 PNG/JPEG 형식·10 MiB·24 MP·전달 경로 일치를 검증한다. 브라우저가 인증 헤더 없이 이미지를 표시해야 하므로 공개 전달 자체에는 직원 세션을 요구하지 않는다.
- 2026-09-11: 페이지 문서의 alt는 자산 기본 alt와 분리한다. 선택 시 기본 alt를 복사하지만 이후에는 문서별 문맥에 맞게 수정하며, 초안·발행 사용 위치에 각각 저장한다.
- 2026-09-11: V13 미디어 자산은 `ACTIVE`와 `ARCHIVED` 상태를 사용한다. 초안·발행 `website_media_usage`가 하나라도 있으면 보관을 거부하고, 보관은 물리 파일 삭제가 아닌 상태 전환으로만 처리한다. 이 선택으로 기존 발행 페이지를 깨뜨리지 않으며 참조를 제거한 자산은 복원할 수 있다.
- 2026-09-11: 자산명·기본 alt·상태 전환은 자산별 낙관적 버전을 요구한다. 페이지 저장의 활성 자산 확인은 `FOR KEY SHARE`, 보관·복원은 `FOR UPDATE`로 잠가 새 참조 저장과 보관이 동시에 성공하지 않게 한다. 기본 alt 변경은 기존 `imageAlt`·`heroAlt`·사용 위치 alt에 전파하지 않는다.
- 2026-09-11: 보관된 업로드 자산의 공개 전달은 404로 차단한다. 내장 `/images/...` 파일은 정적 고객 배포 경로여서 보관만으로 숨길 수 없으므로, 해당 한계는 영구 삭제·CDN 무효화 설계와 함께 후속 단계에서 다룬다.
- 2026-09-11: 새 공개 업로드 이미지 응답은 `Cache-Control: public, max-age=0, must-revalidate`로 제공한다. 자산 보관 뒤 브라우저가 서버 상태를 다시 확인하도록 하기 위한 선택이다. 이 변경 전에 받은 장기 불변 캐시는 서버에서 즉시 무효화할 수 없으므로 자연 만료까지의 한계는 남긴다.
- 2026-09-11: V14의 페이지 보관 대상은 `CONTENT_PAGE`만으로 제한한다. 보관은 현재 공개 본문·메뉴 노출과 `PUBLISHED` 미디어 usage만 비우고 URL·초안·발행 이력·`DRAFT` usage는 보존한다. 복원은 `ACTIVE` 초안으로만 되돌리며 본사가 명시적으로 다시 발행할 때까지 고객 공개를 재개하지 않는다. 이 선택으로 잘못된 즉시 재공개와 복원 가능한 초안의 미디어 보관을 막는다.
- 2026-09-11: V15의 발행 이력 복원은 `ACTIVE CONTENT_PAGE`의 이전 발행본 **콘텐츠만** 현재 초안으로 가져온다. URL·메뉴·부모·공개본은 되돌리지 않으며, 현재 lifecycle/draft/published 버전과 현재 `publishedVersion`보다 이전인 source 페이지·구조·활성 미디어를 확인한다. 복원은 `VERSION_RESTORED` audit과 초안 미디어 usage를 남기고, 고객 공개는 본사의 명시적 재발행에서만 바뀐다.
- 2026-09-11: V16의 발행본 비교는 `CONTENT_PAGE`의 두 immutable snapshot을 읽는 본사 전용 GET으로 둔다. 기준 version은 비교 version보다 작아야 하며 보관된 페이지도 허용한다. 현재 활성 미디어 확인·URL 정규화·초안/공개본/audit/usage 변경은 하지 않고, 관리자가 필드별 차이를 표시한다. 이 선택으로 복원 전에 과거 문서를 검토하되 운영 상태를 바꾸지 않는다.
- 2026-09-11: V17의 일반 페이지 미리보기는 `CONTENT_PAGE` 편집기의 현재 메모리 상태를 읽는 관리자 전용 dialog로 둔다. 저장·발행·보관·복원 API를 호출하지 않고, 고객 parser와 같은 안전한 내장·업로드 미디어 전달 규칙을 적용한다. 이 선택으로 공개 전 콘텐츠 맥락을 확인하면서 초안·공개본·audit·usage를 바꾸지 않는다.
- 2026-09-11: V18의 영구 삭제는 `ARCHIVED CONTENT_PAGE`로 제한하고 lifecycle·draft·published version을 함께 요구한다. page-scoped usage·발행 이력·감사 이력과 page row를 한 트랜잭션에서 지우되 자산 자체는 남긴다. 활성 고객 페이지를 즉시 삭제하지 않고 보관·확인 단계를 거치게 하며, 미래 자식 page는 자동 삭제하지 않는다.
- 2026-09-11: 롯데리조트급 고객 사이트 목표에 맞춰 CMS를 일반 페이지 편집기가 아니라 객실·다이닝·시설·경험·프로모션·안내를 목록과 상세로 운영하는 콘텐츠 플랫폼으로 재정의한다. 현행 `HOME_PAGE`·`HOTEL_LANDING`·`CONTENT_PAGE`와 안전한 초안/발행·미디어·이력 계약은 호환 기반으로 유지하고, 이후 `content_kind`, 깊은 트리, 재사용 block, room type/지점 연결, locale별 번역, 검토·예약 발행, redirect·SEO를 기능 단위로 구현한다. 가격·재고·예약 확정은 계속 Spring 예약 도메인이 소유한다. 상세 설계는 `docs/architecture/lotte-resort-level-cms-functional-design.md`를 따른다.
- 2026-09-11: AI 추천은 설명용으로만 사용한다. 적용 시 고객 웹이 Spring availability를 직접 다시 조회하고, 요청 순서 보호로 현재 예약 조건과 맞지 않는 늦은 응답을 버린다. 따라서 AI나 이전 검색 응답이 가격·재고·선택 가능 offer를 덮어쓸 수 없다.
